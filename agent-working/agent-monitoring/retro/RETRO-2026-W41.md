**Headline: most of this report measures the recording setup, not the work.** Three different instruments
are dark or near-dark, and they share one root cause: which settings a session loads.

- **Session hooks never fire in the live sessions.** Live sessions start from `/mnt/data/Working` (not a git
  repo), or from the main checkout, which is 57 commits behind origin/main. The main checkout's
  `.claude/settings.json` lacks 46 lines of hooks that are on main. The missing hooks are the session-roles
  guard (`tools/sessions/guard.py`), the `manual_actions.py` UserPromptSubmit sampler and the
  `session_start_hook.py` role binding. Evidence:
  - zero `manual_actions*.jsonl` and zero `role_boundary*.jsonl` files exist anywhere, in data/ or in any
    worktree (the files are not gitignored);
  - `session_role` is `unresolved` on 59/59 W41 runs and `None` on all 1321 W41 tool rows;
  - this very session began with the owner typing a role reminder ("continue as agent-working-design").
    That is a textbook `role_reminder`, and nothing recorded it.
  So the session-layer headline metric reads 0 because it is not running, not because the layer works. The
  own-branch guard of PR #359 is likewise not active in any live session. Its AC7 live probe stays undone.
  Also, the guard only emits deny/ask, never allow. Prompts for force-push and `gh pr create` therefore come
  from the static `permissions.ask` list and the missing `gh pr create` allow rule, which the guard ticket
  did not touch.
- **Durations: 0 min average is an artifact.** 57/59 runs are hand closures with `start_ts == end_ts`. The
  implementer measured all 238 hand closures in W40–W41 for TCK-20261006-HAND-CLOSURE-TIME-SOURCE-DESIGN:

  headline averages.

**Addendum 2026-10-06 (amends "Session hooks never fire in the live sessions"; the text above is left as written).** The
SessionStart hook does fire in sessions that run inside a worktree new enough to have it: `.git/session-roles/` holds
bindings for agent-working-implementer, rpg-implementer and rpg-planner. What holds is narrower: the project hooks and agent
types are dark in sessions started from `/mnt/data/Working` or a stale checkout, and `manual_actions`/`session_role` are dark
everywhere. The follow-up investigation (`TCK-20261006-LIVE-SESSIONS-RUN-STALE-OR-NO-PROJECT-HOOKS`, Scope 6) found why:
the sampler and `session_role` stamping reached main only on 2026-10-05T17:43+07, a day before this retro, so earlier
prompts and runs could not be recorded. Of 63 W41 runs on main, 33 have no `session_role` field at all (the retro table
prints them as `unresolved`) and 30 are stamped `unresolved` because their closing session had no binding. The sampler
itself works (run by hand from a current worktree it writes a row); 9 of 20 local worktrees still lack the sampler hook.
The "59/59 unresolved" figure therefore mixes "predates the field" with "no binding".
