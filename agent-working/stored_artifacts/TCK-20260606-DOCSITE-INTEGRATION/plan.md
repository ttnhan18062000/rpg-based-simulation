### Phase 3 — Status Badges (AC 4)

**Approach:** Swizzle `DocItem/Layout` to wrap the page and inject a colored badge above the document content based on `frontMatter.status`.

**Files to create:**

```
website/src/theme/DocItem/Layout/index.js   (swizzled component)
website/src/css/custom.css                   (badge styles + archive styles)
```

**`website/src/theme/DocItem/Layout/index.js`:**

```jsx
import React from 'react';
import Layout from '@theme-original/DocItem/Layout';
import { useDoc } from '@docusaurus/plugin-content-docs/client';

const STATUS_COLORS = {
  authoritative: { bg: '#1a7f37', color: '#fff' },
  active:        { bg: '#0969da', color: '#fff' },
  historical:    { bg: '#9a6700', color: '#fff' },
  archive:       { bg: '#6e7781', color: '#fff' },
};

function StatusBadge({ status }) {
  if (!status) return null;
  const style = STATUS_COLORS[status] || { bg: '#6e7781', color: '#fff' };
  return (
    <span style={{
      display: 'inline-block',
      padding: '2px 10px',
      borderRadius: '12px',
      fontSize: '0.75rem',
      fontWeight: 600,
      textTransform: 'uppercase',
      letterSpacing: '0.05em',
      backgroundColor: style.bg,
      color: style.color,
      marginBottom: '0.75rem',
    }}>
      {status}
    </span>
  );
}

export default function DocItemLayoutWrapper(props) {
  const { frontMatter } = useDoc();
  return (
    <>
      <StatusBadge status={frontMatter.status} />
      <Layout {...props} />
    </>
  );
}
```

**Notes:**
- `useDoc()` is available in `@docusaurus/plugin-content-docs/client` (Docusaurus 3.x).
- This approach works across all four plugin instances because `DocItem/Layout` is the shared theme component.
- The swizzle wrapper pattern is safe — it delegates to `@theme-original/DocItem/Layout`.
- The directory `website/src/theme/DocItem/Layout/` must be created (Docusaurus discovers theme overrides by path convention, no registration needed).

**`website/src/css/custom.css`** — also contains archive visual differentiation (Phase 5).

To wire the custom CSS, update `docusaurus.config.js` presets entry:
```js
theme: { customCss: [require.resolve('./src/css/custom.css')] },
```

### Phase 4 — Artifact Index Page Generator (AC 5)

**Script:** `tools/generate_artifact_pages.py`

**Behavior:**
- Reads `docs/REGISTRY.yaml`
- Filters entries where `type == 'ticket'` and `artifact_files` is non-empty
- For each, resolves the `stored_artifacts/{ticket_id}/` directory
- Writes `stored_artifacts/{ticket_id}/index.md` if it does not exist or is older than REGISTRY.yaml (idempotent)
- Handles partial dirs (lists only present artifact files)
- Supports `--dry-run` flag (prints what would be written, no files created)

**index.md template per ticket:**
```markdown
---
title: "{ticket_id}"
description: "Artifact landing page for {ticket_id}"
status: {ticket_status or 'historical'}
layer: misc
authority: P2
audience: agent
tags: {ticket_tags}
---

# {ticket_title}

**Ticket:** {ticket_id}
**Date:** {ticket_date}
**Tier:** {ticket_tier}

## Artifacts

{list of links to present artifact files}
```

**Makefile integration:** Add a `docs-artifacts` target that runs this script. Update `docs-serve` and `docs-build` to depend on `docs-artifacts`:
```makefile
docs-artifacts: ## Generate stored_artifacts index pages
    python3 tools/generate_artifact_pages.py

docs-serve: docs-artifacts
    cd website && npm run start

docs-build: docs-artifacts
    cd website && npm run build
```

**Verify existing Makefile lines** before editing (currently lines 137/140/143 in Makefile) — update deps, do not duplicate targets.
