# Test Plan — TCK-20260606-DOCSITE-INTEGRATION

## Testing Approach

This ticket produces web UI and build artefacts, not Python source. Tests fall into three categories:
1. **Build-time validation** — `make docs-build` exits 0, no broken links fatal
2. **Runtime spot-checks** — `make docs-serve` + manual verification against each AC
3. **Script unit tests** — `tools/generate_artifact_pages.py` correctness tested in isolation

No pytest suite exists for the Docusaurus layer. Acceptance is verified by running the site and checking each AC.

---

## Pre-flight Checks

Before running any test:
- [ ] `make docs-registry` has been run to produce a fresh `docs/REGISTRY.yaml`
- [ ] `cd website && npm install` is up to date
- [ ] `tools/generate_artifact_pages.py` has been run (generates `stored_artifacts/*/index.md`)
- [ ] No leftover `website/.docusaurus/` cache from a broken prior run (`npm run clear` if needed)

---

## Test Cases

### T1 — `make docs-build` succeeds

**Command:** `make docs-build`
**Pass:** exit code 0, output contains "Success!", no `[ERROR]` lines about broken links that are fatal
**Fail:** non-zero exit or any `[ERROR]` line referencing a missing file that was generated by this ticket

**Notes:** `onBrokenLinks: 'warn'` means broken external links produce warnings, not failures. Internal broken links (e.g. index.md referencing a missing artifact file) will also warn. Review warnings after build and fix any that are generated-file issues.

---

### T2 — All four sections reachable

**Command:** `make docs-serve` (opens http://localhost:3000)
**Steps:**
1. Navigate to http://localhost:3000/docs/ — docs section loads, sidebar visible
2. Navigate to http://localhost:3000/tickets/ — tickets section loads
3. Navigate to http://localhost:3000/artifacts/ — artifacts section loads
4. Navigate to http://localhost:3000/archive/ — archive section loads
**Pass:** All four load without 404 or JS error in console

### T3 — Docs sidebar grouped by layer

**Steps:**
1. Open http://localhost:3000/docs/

### T4 — Tag index pages

**Steps:**
1. Open any doc that has a `tags:` field (e.g. `docs/certification/harness_architecture.md` — tags: [certification, harness, testing])

**Pass:** Tag index page loads and lists the correct docs
**Fail:** 404 on tag page, or no tag chips shown on docs
