# Investigation — TCK-20260713-MONITORING-VALIDATE-INDEX-MIGRATE

## Current Behavior

### `tools/agent-monitoring/validate.py` (source of the two/three functions in question)

- `LEGACY_COMPLETION_FIELDS` (validate.py:31) and `LEGACY_TERMINAL_STATUS_VALUES` (validate.py:37-41) — module-level allowlists.
- `_record_is_complete(rec)` (validate.py:44-51) — the **only** function that reads either allowlist.
- `compute_drift_report(runs, events)` (validate.py:61-121) — null-required-field counts on `runs` (`workflow`/`tier`/`final_status`, raw fields), plus phase/agent/tier vocabulary-drift Counters built by hand-iterating `events`/`runs`. **Does not reference `LEGACY_COMPLETION_FIELDS` or `LEGACY_TERMINAL_STATUS_VALUES` anywhere in its body.**
- `compute_tool_count_drift_report(events, tools)` (validate.py:124-167) — cross-checks `events[].tool_call_count` against a `Counter` of `tools` grouped by `(run_id, seq)`. **Also does not reference either allowlist.**
- `compute_multi_invocation_collision_report(events)` (validate.py:170-193) — added by `TCK-20260728-MONITORING-PAUSE-RESUME-SEQ-COLLISION` (done, after this ticket was filed). Groups events by `(run_id)` where `phase == "Scope" and seq == 1`, flags `run_id`s with count > 1. Identical shape to the two functions above: pure, read-only, non-gating, hand-rolled `Counter` over a raw `events` list.
- `load_jsonl(path)` (validate.py:196-208) — tolerant per-line JSON loader, warn-and-skip on malformed lines. Reused directly by `build_index.py`, `src/api/agent_ops_dashboard/ingest.py` (`validate.load_jsonl`), and `tools/agent-monitoring/legacy_reader.py`.
- `main()` (validate.py:211-285) — loads all 3 JSONL files via `load_jsonl()`, runs the incomplete-run check (uses `_record_is_complete`, the **actual** consumer of the two allowlists — not named in this ticket's Scope), the no-events check, the working_log cross-check, then prints all three `compute_*` reports in sequence and a final `OK:` summary. Never gates (only `errors` — "run with no events" — force `sys.exit(1)`; everything else is warning-only, consistent with the ticket's "read-only, non-gating" requirement).

### `tools/agent-monitoring/build_index.py` (shipped sibling, `TCK-20260713-MONITORING-SQLITE-INDEX`, done)

Reads `runs`/`events`/`tools` JSONL once each, writes `agent-monitoring-index/monitoring.db` (gitignored, full-rebuild-only, on-demand via `make agent-monitoring-index`, never wired into `test`/`ci`/`all`). Schema (build_index.py:52-96):

- `runs(id, run_id, workflow, tier, start_ts, resolved_status, is_complete, raw_json)` — `resolved_status` computed via `generate_retro._resolve_status()` (imported, not reimplemented); `is_complete` computed via `validate._record_is_complete()` (imported). Note: **`final_status` is not a typed column** — only the merged `resolved_status` is. `tier`/`start_ts`/`workflow` are raw pass-through typed columns.
- `events(id, run_id, seq, workflow, phase, agent, raw_json)` — `run_id`, `seq`, `phase` are all typed columns, indexed together (`idx_events_run_id_seq ON events(run_id, seq)`). `phase`/`agent` are raw pass-through (not case-normalized — case-fold normalization is explicitly deferred to the separate `TCK-20260713-MONITORING-RETRO-INDEX-MIGRATE` sibling per that ticket's own Scope Guards). **`tool_call_count` is not a typed column** — only present inside `raw_json`.
- `tools(id, run_id, seq, workflow, tool, raw_json)` — `run_id`/`seq` typed and indexed (`idx_tools_run_id_seq`); 3 confirmed off-schema records structurally excluded (missing `run_id`/`seq`/`tool` keys), never coerced.

### `tools/agent-monitoring/query.py` (shipped sibling migration, `TCK-20260713-MONITORING-QUERY-INDEX-MIGRATE`, done — the direct precedent for HOW to migrate)

- `open_index(db_path)` (query.py:29-36) — `if not db_path.exists(): print(actionable "run make agent-monitoring-index first" message, file=sys.stderr); sys.exit(1)`, else `sqlite3.connect()`. Does **not** special-case a corrupt db — that raises its native `sqlite3` exception unmasked (documented, tested precedent: don't conflate "missing" with "corrupt").
- `load_runs_from_index(conn)` / `load_events_from_index(conn)` (query.py:39-51) — `SELECT ... raw_json FROM {runs|events} ORDER BY id`, then `json.loads(raw_json)` per row, returning plain dicts. `load_runs_from_index` additionally injects `_resolved_status` from the SQL column into each returned dict (used later for `--status` filtering against the resolved value, not raw `final_status` — the one intentional divergence documented in `INFRA-289`).
- `filter_runs`/`filter_events` (query.py:104-133) — unchanged Python-side comparison logic; **only the data source changed**, not the comparison predicates. This is the exact strategy the migration plan (`stored_artifacts/TCK-20260713-MONITORING-QUERY-INDEX-MIGRATE/plan.md`) calls "the lowest-risk path to field-for-field parity because the comparison logic itself doesn't change, only the data source."
- `RUNS_FILE`/`EVENTS_FILE`/`load_jsonl()` were deleted entirely from `query.py`; a source-text architecture guard (`test_query_py_has_no_direct_jsonl_reads`) enforces zero residual direct-JSONL-read references.
- `query.py` never touches `tools.jsonl`, so **no `load_tools_from_index()` helper exists yet anywhere in the codebase** — this ticket needs to build one from scratch for `compute_tool_count_drift_report` (and `compute_multi_invocation_collision_report`, if folded in, needs `load_events_from_index()` only, which already exists as a pattern).

## Risks and Open Questions

1. **[BLOCKS PLAN] The ticket's Request Summary/Scope premise about `LEGACY_COMPLETION_FIELDS`/`LEGACY_TERMINAL_STATUS_VALUES` does not match the current code.** Neither `compute_drift_report()` nor `compute_tool_count_drift_report()` references either allowlist anywhere in their bodies (verified by direct read, validate.py:61-167). The only consumer is `_record_is_complete()` (validate.py:44-51), called from `main()`'s incomplete-run check (validate.py:232-236) — a piece of logic **not named in this ticket's Scope** (only the two `compute_*` functions and, per the Assumptions note, possibly `compute_multi_invocation_collision_report` are named). The idea doc's own migration-target table (line 59) already frames the real duplication correctly as hand-rolled `Counter` groupings, not the allowlists. **This needs an explicit Plan-phase (or human) decision**: either (a) treat AC3 as inapplicable to the two named functions and drop/reinterpret it (recommended — see below), or (b) expand Scope to also migrate `main()`'s incomplete-run check to read the index's precomputed `is_complete` column, which is a materially bigger change than the ticket currently describes and changes `validate.py`'s reliability contract (see risk 2). Do not silently assume either answer.
2. **AC3's "removed entirely" option is not viable without touching out-of-scope files.** `tools/agent-monitoring/legacy_reader.py` imports `LEGACY_COMPLETION_FIELDS`/`LEGACY_TERMINAL_STATUS_VALUES` directly from `validate.py` (with an explicit assertion tying its own logic to validate.py's copy — `legacy_reader.py:16-29`), and `build_index.py` also imports both directly (`build_index.py:33-38`). Deleting the names from `validate.py` breaks both. "Reduced to a single reference to the index's shared normalization" is the only literal-AC3 option left standing, but `validate.py` is already the **canonical upstream definer** that `build_index.py` imports *from* — there is no "index normalization" for `validate.py` to point back at without inverting the import direction (a materially larger, unrequested architectural change). Recommend treating AC3 as satisfied-by-inaction for the two named functions (since they never used the allowlists) and flagging this explicitly in `plan.md`'s Anti-Drift Notes so a future reader doesn't "fix" it later.
3. **`validate.py` currently has zero precondition on the index existing.** `make agent-monitoring-validate` runs standalone (Makefile:266-267) and is not wired into `test`/`ci`/`all`, unlike `query.py`, which (post-migration) hard-requires `make agent-monitoring-index` to have been run first (`open_index()` → `sys.exit(1)` if missing). If `compute_drift_report`/`compute_tool_count_drift_report` (and possibly the collision report) start sourcing data from the index, `validate.py` inherits that same hard precondition — a real behavior/usability change for anyone running `make agent-monitoring-validate` on a fresh checkout without ever having built the index. **Recommend mirroring `query.py`'s precedent exactly** (actionable stderr message + `sys.exit(1)`) for consistency rather than inventing a different fallback (e.g., auto-building the index inline), but this is a decision the Plan phase should state explicitly, not assume silently, since it changes `validate.py`'s current zero-precondition usability.
4. **AC2's "13 existing tests" is stale.** `tests/tools/test_validate_agent_monitoring.py` currently has **15** test functions (verified by direct count), not 13 — `test_multi_invocation_collision_report_detects_duplicate_scope_seq1` and `test_multi_invocation_collision_report_is_read_only` were added later by `TCK-20260728-MONITORING-PAUSE-RESUME-SEQ-COLLISION`, exactly the same scope-drift the ticket's own Assumptions section already flags for the function itself. `test_canonical_vocabulary_single_sourced` (the 15th, unrelated to drift reports — checks `record_events.py`/`validate.py` share the same `vocabulary.py` module object) must also keep passing regardless of what's migrated. Plan/AC2 language should say "all tests in the file" or explicitly say 15, not 13.
5. **`raw_json` round-trip fidelity.** `build_index.py` stores `json.dumps(record, sort_keys=True)`; reading it back via `json.loads()` must reproduce an equal dict for every field these three functions inspect (`workflow`, `tier`, `final_status`, `phase`, `agent`, `run_id`, `seq`, `tool_call_count`, `tool`). No lossy type coercion is expected (JSON round-trips are lossless for the types present here), but this should be explicitly asserted by the regression-parity test, not assumed.
6. **`events.workflow` (typed column) is not equivalent to `compute_drift_report`'s own `infer_workflow(e.get("run_id") or "")` call.** `build_index.py`'s `_ingest_events` sets `workflow = record.get("workflow") or infer_workflow(run_id)` — i.e., it prefers the raw `workflow` field if present, falling back to inference only when absent. `compute_drift_report` (validate.py:76) **always** calls `infer_workflow(e.get("run_id") or "")` directly, ignoring any raw `workflow` field on the event entirely. If any live event record carries an explicit (and potentially different) `workflow` field, sourcing from the typed `events.workflow` column instead of recomputing `infer_workflow(run_id)` in Python would silently change `compute_drift_report`'s phase-drift grouping. **Do not read the typed `workflow` column for this purpose** — continue calling `infer_workflow()` directly on the `run_id` field extracted from `raw_json`, exactly as today, to guarantee AC2's identical-output requirement.

## Anti-Drift Hazards

- **Do not migrate `main()`'s incomplete-run check** (the actual `_record_is_complete`/`LEGACY_*` consumer) as an implicit side effect of "cleaning up" AC3 — it is not named in Scope, and doing so silently would both violate the Out-of-Scope boundary and reopen risk #3 above (index-precondition change) for a piece of logic nobody asked to move.
- **Do not read typed index columns as a shortcut where the current function computes something different.** `events.workflow` (raw-field-preferred) vs. `infer_workflow(run_id)` (always-inferred) is the concrete trap (risk #6). Prefer the "load `raw_json`, `json.loads()`, feed the unchanged function body" strategy throughout — the same strategy `query.py`'s migration used — rather than trying to use typed columns as a performance/elegance shortcut; typed-column shortcuts are exactly where field-for-field parity (AC2) silently breaks.
- **Do not normalize phase/agent casing while migrating.** `compute_drift_report` must keep surfacing casing variants as distinct entries (confirmed by INFRA-283's explicit "deliberately, verifiably untouched" framing) — this is a different, deferred concern (`TCK-20260713-MONITORING-RETRO-INDEX-MIGRATE`'s territory), not this ticket's.
- **Do not touch `build_index.py`'s schema** to add typed `final_status`/`tool_call_count` columns "to make this easier" — explicitly out of scope (this ticket's Out of Scope section, and `TCK-20260713-MONITORING-SQLITE-INDEX`'s plan Scope Guards, which lists this ticket as a pure consumer). `raw_json` extraction is sufficient and is the precedented approach.
- **Do not change `load_jsonl()`'s signature or behavior.** It's reused verbatim by `legacy_reader.py` and `src/api/agent_ops_dashboard/ingest.py` (`validate.load_jsonl`), both out of scope. If `main()` stops calling `load_jsonl(RUNS_FILE)`/`load_jsonl(EVENTS_FILE)`/`load_jsonl(TOOLS_FILE)` directly (replacing with index reads), `load_jsonl()` itself must still exist unmodified for those other consumers — do not delete it the way `query.py` deleted its own copy (query.py never shared `load_jsonl` externally the way `validate.py`'s copy is shared).
- **Do not silently drop the `compute_multi_invocation_collision_report` question.** The ticket's own Assumptions section flags it as needing an explicit fold-in-or-defer decision — see recommendation below; whichever way Plan decides, it must be stated, not left implicit.
- **Keep `main()`'s non-gating exit-code contract exactly as-is**: only "run with no events" pushes to `errors` (→ `sys.exit(1)`); everything else (incomplete runs, working_log cross-check, and by extension anything the three `compute_*` report functions surface) stays warning-only/purely-additive. A migration must not accidentally make a missing/stale index a hard error that changes this contract's shape (beyond the already-precedented "index file missing" exit-1 case discussed in risk #3, which is about *invocation*, not about report *content* gating anything).

## Recommendation on `compute_multi_invocation_collision_report()` (ticket's own flagged open question)

**Fold it in.** Evidence:

1. **Identical shape.** Pure function, takes a raw `events` list, returns a formatted string, called from `main()`, never gates (validate.py:170-193) — the same "read-only, non-gating, hand-rolled `Counter`-over-raw-`events.jsonl`" pattern as `compute_drift_report`/`compute_tool_count_drift_report`, confirmed by direct code comparison, not assumption.
2. **Its data needs are a strict subset of what's already typed and indexed.** It only reads `run_id`, `seq`, `phase` from each event — all three are **typed columns on the `events` table already**, and `(run_id, seq)` is the table's actual index (`idx_events_run_id_seq`, build_index.py:82). This makes it the *most* directly index-supported of the three functions (more so than `compute_drift_report`, which needs `final_status`/raw-`workflow`-field fidelity via `raw_json`, and `compute_tool_count_drift_report`, which needs `tool_call_count` via `raw_json`).
3. **Folding it in requires zero `build_index.py` schema changes**, so it doesn't cross this ticket's own Out-of-Scope boundary ("Building or modifying `tools/agent-monitoring/build_index.py`... is sibling ticket's responsibility").
4. **Leaving it out reintroduces the exact problem this ticket exists to solve.** If only 2 of 3 sibling functions migrate, `main()` would need to source `events` from the SQLite index for two functions and from raw `events.jsonl` for the third within the same run — two live data-loading paths for the same file, which is the duplication this ticket's premise (per the idea doc) is meant to eliminate.
5. Its own 2 tests (`test_multi_invocation_collision_report_detects_duplicate_scope_seq1`, `test_multi_invocation_collision_report_is_read_only`) already live in the same test file and already count toward AC2's "existing tests continue to pass" bar regardless of the fold-in decision — folding in the migration doesn't add new regression surface, it just closes the gap the ticket's Assumptions section already anticipated.

Net effect if folded in: `main()` needs one `load_events_from_index(conn)` call shared by all three report functions (`compute_drift_report`, `compute_tool_count_drift_report`, `compute_multi_invocation_collision_report`), plus one new `load_runs_from_index(conn)` and one new `load_tools_from_index(conn)` (the latter genuinely new — no precedent exists yet, `query.py` never touched `tools.jsonl`).
