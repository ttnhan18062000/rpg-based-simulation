# Investigation — TCK-20261003-PREK-GIT-HOOKS-OPT-IN

Context scan: `search_docs` (hits: the post-commit reindex ticket TCK-20260612-LOCAL-CTX-OPS, the provider-hook policy) and `graphify query` (no useful nodes) first; facts below are from the follow-up reads and runs.

## What is installed where today
- `.git/hooks` of the main checkout is the **common** hooks directory of every worktree (`git rev-parse --git-common-dir` -> `.git`). It currently holds only `post-merge` (copied by `make setup-merge-drivers` from `tools/hooks/registry_post_merge_regen.sh`); `post-commit` is not installed on this machine, and `core.hooksPath` is unset.
- `make install-hooks` does `cp tools/hooks/post-commit-reindex.sh .git/hooks/post-commit`, which **overwrites** whatever post-commit hook is there. The new opt-in target must not copy that behaviour.
- The reindex hook is a no-op unless `agent-working/.index/knowledge-index/knowledge.db` exists and docs/ or `agent-working/tickets/done/` changed.

## prek (scratch env, 0.5.4 from PyPI; a single binary wheel, installs with uv)
- `prek install --hook-type pre-commit` writes `.git/hooks/pre-commit` (marked "File generated by prek").
- With a **foreign** pre-commit hook already there, prek moves it to `pre-commit.legacy` and runs it too ("migration mode"; `--force` would remove legacy hooks). Nothing is lost, which satisfies "neither overwrites the other".
- Running install twice is idempotent (same file, same legacy hook). `-f/--force` overwrites shims.
- Config: `.pre-commit-config.yaml`; `repo: local` hooks with `language: system` need no environment build or network.

## Design consequences
- A new installer script (`tools/hooks/install_git_hooks.py`, testable against a scratch repo) does: (1) post-commit: install `tools/hooks/post-commit-reindex.sh` only if absent; identical -> no-op; different existing -> leave it and say so (never overwrite); (2) `prek install --hook-type pre-commit` (idempotent, preserves a foreign hook as legacy); and an uninstall that removes only what it installed. `make install-prek-hooks` / `make uninstall-prek-hooks` call it. Nothing else calls it (static test).
- The ratchet filter for staged files is a new small module (`tools/code_health/staged_ratchet.py`): ruff on the staged `src/**/*.py` files (same safe-path rule as the SARIF module), compared with the registry per ratchet unit (a (file, code) group within its ceiling passes), printing the ratchet's NEW / WORSE report.
- prek goes into the `dev` group (all CI jobs sync it; tests of the installer need the binary everywhere), pinned exactly like the other tools.
- Timing and behaviour must be shown in a **scratch clone**, never the shared hooks.
