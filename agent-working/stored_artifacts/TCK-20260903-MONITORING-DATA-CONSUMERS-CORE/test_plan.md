## Anti-Drift Test Guards

- **`tests/tools/test_query.py`'s `for forbidden in ("RUNS_FILE", "EVENTS_FILE", "load_jsonl")`
  architecture guard (line 394)** must keep passing unmodified — proves this ticket's fix never
  leaks a direct-JSONL-read dependency into `query.py`, which must remain a pure SQLite-index
  consumer.
- **`tests/tools/test_build_index.py::test_build_index_never_touches_write_path_modules`** must
  keep passing — any new glob-resolution helper must stay stdlib-only (`Path.glob()`), never
  importing `tools/agent-monitoring/writer.py`.
- **`tests/tools/test_agent_monitoring_manifest.py::test_manifest_source_never_calls_full_file_
  read_methods`** (AST guard banning `read_text`/`read_bytes`/`readlines`/`read`) must keep
  passing — the streaming per-line design (`open(path, "rb")` + line iteration) must survive the
  glob-target redesign.
- **`tests/tools/test_generate_retro.py`'s existing source-text architecture guards**
  (`assert "load_jsonl(RUNS_FILE)" not in source`, `assert "EVENTS_FILE" not in source` /
  `"RUNS_FILE" not in source` / `"DEFAULT_TOOLS_FILE" not in source` at lines 1107-1122, 1443-1444,
  1794-1795, 2027-2029, 2362-2364) pin specific functions (`main()`, `_update_index()`, and others)
  to route through `_load_runs_and_events()`/the module-level constants rather than re-deriving
  their own file reads. Re-run these explicitly; a fix that accidentally introduces a new bespoke
  file-read inside one of these guarded functions would silently violate this repo's established
  single-read-path discipline.
- **`test_build_manifest_shape_against_real_corpus`'s exact-3-records/exact-filename-set assertion**
  must never regress to one record per week folder — this is the single most likely
  scope-creep failure mode for `manifest.py`'s fix (see investigation.md's Anti-Drift Hazards).
- **`test_weight_sensitivity_check_real_multi_week_tools_and_events_produce_nonzero_score` must
  never be weakened to a same-week-only variant** — a narrower current-week-only fix would pass a
  weaker test while leaving the cross-week case (a paused/resumed session whose tool-call rows land
  in an earlier week) silently broken, exactly the class of regression child 1's own
  `record_events.py` fix and regression test guarded against.
- **No test in this ticket's new set should assert against `agent-monitoring/tools/` (the prior
  epic's now-dead flat shard directory) or `agent-monitoring/{runs,events,tools}.jsonl` (the
  original monolithic paths) as a *current* read target** — only as historical-context strings (e.g.
  asserting a doc *no longer* mentions them). A test that accidentally keeps passing against a dead
  path (return `[]` on missing-path, matching some assertion of "empty") would silently mask a
  regression rather than catch one — cross-check every new/rewritten test asserts a *nonzero*,
  *real* result wherever the underlying data is nonzero, not just "did not crash."
