# Event catalog inventory (read-only, owner decision 80 (i))

Base `4de05711f`. 138 event types: 69 measured in the runs, 69 with a producer in `src/` that never fired in 15 runs (3 worlds x seeds 42-46 x 5000 ticks). Counts are per world, summed over the 5 seeds (`F` frontier_living_world, `U` urban_political, `C` crowded_frontier); per-seed counts are in `event_counts_per_seed.tsv`.

## 0. What matters most (details below)

1. **The event file is lossy once 5000 CRITICAL events have accumulated** (section 1). `biological_state_changed` is CRITICAL, so in FULL mode from about tick 3300 the file and the SimQ feed lose every INFO and WARNING event, including the shutdown tally events the rpg gate reads (`rpg_gate_ledger_tally`, `death_ledger_tally`, `starvation_channel_tally`: present only in the three crowded_frontier runs that stayed under 5000). The gate is safe today only because LIGHT mode does not emit `biological_state_changed` (it is mode-gated).
2. **`combat_resolved` is emitted** (405 / 55 / 338 in F / U / C); the 'known never emitted' list should not carry it. Truly without a producer: `attrition_threshold_crossed` and `camp_constructed`. `project_*` types are reachable only through the translation of `StrategicProjectChanged` / `StrategicDetourCreated` (the table shows what fired).
3. **Alert events never reach SimQ or the file**: `GOLD_HOARDING`, `INFLATION_SPIRAL` and the other economy alerts go to the kernel's listeners only.
4. **Events built in authoritative code and dropped**: `belief_contradiction` and `lead_contradiction_resolved` are built in the refine pass and discarded at `pipeline.py:526` (the extractor re-derives them from the state diff); `leadership_changed`, `betrayal_desertion`, `clan_member_left` and `clan_succession` are buffered on class attributes that no production code reads (section 3c).
5. **Zero `InvariantViolation` events** in 15 runs: no hard-law violation fired.
6. **Economy events never fire in these three worlds**: `gold_sink_fired`, `trade_executed`, `shop_transaction`, `item_crafted` and `quest_reward_dispensed` are all 0 (section 3a), although the Economy pillar listens to them.
7. Counts are FULL observability mode with default feature flags; the default LIGHT mode emits fewer types (mode gates are listed per type).

**The event file is NOT lossless at 5000 ticks, so the counts do not come from it.** In 12 of the 15 runs `simulation_events.jsonl` holds fewer lines than the recorder counted (F / R down to 0.58), although the recorder stayed in NORMAL, `events_dropped_by_mode` and `queue.dropped_count` are 0, the drain worker is alive and healthy, and the queue is empty at the end. Cause (read from `event_recorder.py` `record()`): the in-memory buffer holds 5000 events; when it is full, `record()` evicts the oldest event of the lowest severity below CRITICAL, and when everything in it is CRITICAL it drops the incoming non-critical event and returns BEFORE the queue push. `biological_state_changed` is emitted at severity CRITICAL (14,083 in urban_political seed 42), so once 5000 of them have accumulated (around tick 3300 in that run) every later INFO and WARNING event is dropped from the file and from the SimQ feed (`quality_fn` is fed from the same queue); only the CRITICAL ones still get through. `dropped_event_count` is the counter that shows it (242,360 in that run); the 'file stops keeping events from tick' column is where the file's per-500-tick count falls below 90% of the recorder's. This is a read-only finding for the designer; nothing here was changed.

The count used in the table is the per-type maximum of R, L and F: R is incremented on every `record()` call before any filter, L sees every event handed to the kernel's listeners, and F is shown only as a cross-check. The 3 extra file lines per run are the three shutdown tally events, which are written outside `record()`.


SimQ note: the SimQ hub is built only when `build_feed_from_env()` returns a feed, so the runs have no hub; the SimQ column is static (scorer `EVENT_TYPES` after `quality_hub._translate`, whose payload-conditional translators map to the outputs listed in the table).
