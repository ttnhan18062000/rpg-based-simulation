# TCK-20261009-IGNORE-POSTURE-IS-NEVER-PRODUCED-SO-KEEP-WALKING-CANNOT-FIRE-DECISION-32

## Title
`CombatEngagementDecisionService` never returns IGNORE for a subject beside an unengaged hostile, so decision 32's "keep walking and pay knowingly" outcome is built but unreachable.

## Status
OPEN

## Tier
standard

## Type
feature

## Priority
P3

## Request Summary
This is a follow-up from Lane A's D32 batch ("notice and decide"). In the pinned 5x3, 102 to 121 decisions per run are taken beside an unengaged hostile. The posture split is avoid, engage, watch, skirmish, probe and retreat, and IGNORE is 0 in every world. The KEEP_WALKING branch is unit-tested but fires 0 times. The designer ruled (and the user confirmed, 2026-10-09) that this is acceptable for now, disclosed, with this ticket to make the outcome reachable. WATCH now maps to a typed stand-and-observe wait.

## Scope
1. Trace why the posture service never yields IGNORE for these pairs: the inputs, the thresholds, and when IGNORE is meant to arise.
2. Propose to rpg-planner, with the designer's reading, when a passerby should ignore an adjacent hostile (e.g. a weak or non-threatening hostile, the subject's goal priority, a low perceived danger under KNOW-04). Use no new tuning dial; reuse existing terms.
3. Build it, then measure the IGNORE share, OA hits, deaths and alive (pinned 5x3).

## Out of Scope
- WATCH's mapping (ruled).
- A movement-layer freeze (rejected by decision 32).

## Acceptance Criteria
- IGNORE occurs in the corpus under the stated conditions. A kernel scenario shows a passerby that ignores a harmless hostile, walks on, and pays the opportunity attack, with a control arm.
