# TCK-20261004-ARCH-VERIFY-TESTS-READ-EVIDENCE

## Status

## Request Summary
`test-architecture-reviewer` (Epic C criterion 2, run 2, 2026-10-04) measured 2 of 2 production Architecture-Verify runs where the reviewer did not read the changed test files, yet returned `test_quality_findings: []` with APPROVED. The schema description (`.claude/workflows/implement-ticket.js:1179`) says an empty list "means the changed tests were read and are clean", so an empty list cannot be told apart from not looking. Second finding, verified in `tools/agent-monitoring/arch_verify_read_check.py:67-70`: `changed_test_files()` runs only `git diff --name-only --diff-filter=d <base>...HEAD`, so a hand-orchestrated run that reviews before commit (the test file untracked) reports "the branch changes no file under tests/" and 0 attributed rows.

## Scope
1. Checker: also include working-tree changes (`git diff --name-only --diff-filter=d HEAD`) and untracked files (`git ls-files --others --exclude-standard`) under `tests/`, de-duplicated with the committed set; report which source each file came from. Test for committed-only, uncommitted-only, untracked-only, deleted-excluded.
2. Evidence: add an optional array field `tests_read` (paths) to the Architecture-Verify output schema, carried into the events row like `test_quality_findings`. The reviewer lists each changed test file it opened.
3. Advisory comparison (never a verdict or workflow gate; proportionate, per the recorded rule against strict blocking gates over monitoring data): the checker and the event record flag changed test files absent from `tests_read` and from the tools-shard Read rows; `test_quality_findings: []` with a non-empty missing set is reported as "unverified", not "clean".
4. One prompt line in `.claude/agents/architecture-reviewer.md` (near line 123): open every changed test file before reporting, list them in `tests_read`, an empty findings list is a claim about files you read.
5. Reword the schema description at implement-ticket.js:1179 so it no longer asserts what it cannot verify.

## Out of Scope
- Making a missing read block APPROVED. Re-measuring Epic C criterion 2 (stays NOT DEMONSTRATED until the reviewer's own session decides).

## Acceptance Criteria
1. The checker lists an untracked and an uncommitted-modified test file on an uncommitted run.
2. `tests_read` round-trips schema, events shard and `record_events.py` validation.
3. An approved run with `[]` findings and an unread changed test is reported "unverified".
4. Prompt line present; no verdict change anywhere.
