# Investigation: session-layer M0 harness spike (class 1)

Harness: Claude Code 2.1.286, Linux, 2026-10-03. Author: agent-working-design (draft; the implementer commits).
Raw evidence: `evidence/*.jsonl` next to this file (stdout and hook logs of the disposable runs; hook logger
`log_hook.py`, probe settings `probe_settings.json`, agent files `session-probe*.md`). No `.json` files.

## Method

Disposable `claude -p --model haiku --setting-sources project` child sessions in a scratch git repo, with project
settings whose hooks log each payload and the `CLAUDE*`/`SESSION*` environment. Every **negative or blocking
claim has a positive control**: a run with no hook decision (and one with `allow`) executes the command and leaves a
side-effect file, so "blocked" means the effect file is absent while the control's is present. Probe transcripts
were deleted afterwards (verified: no `*m0*` or `*other*` project directories remain).

Classes (ticket Scope): **1** = checkable by the agent alone (done here); **2** = needs a live interactive terminal
or a deliberate crash and the owner's opt-in (not run).

Documentation versus observation: the plan assumed `agent_type` and `SESSION_ROLE` are reliable binding signals at
`SessionStart` and that a hook crash is "unproven" for fail-closed. Observation: neither holds on resume, and a hook
crash fails **open**. The plan is updated from the observation (see the patch).

## Outcome

**Decision: ADJUST** sections 5, 6.1 and 10; **HOLD** section 9.5. No item observed contradicts the design's core
(role id as identity, sessions disposable, recovery by role id, guardrail not sandbox); every finding changes a
mechanism, not the architecture.

1. **Section 5, binding**: resume must resolve the role from `session_title`, not from `SessionStart`'s `agent_type`
   or the environment; a `PreToolUse` guardrail resolves by `session_id` from the binding record.
2. **Section 5, launcher**: generated `session-<role>.md` files enter every plain session's Agent roster; each needs
   a "launcher-only, never spawn" description, or another location. Chosen in M1 with a spawn probe.
3. **Section 10, guardrail**: only exit 2 or a JSON deny blocks. The script must catch every exception and exit 2 for
   authority classes; keep the matcher narrow; harness permission rules become the primary backstop for command
   patterns. "Fail-closed" is still not claimed beyond that discipline.
4. **Section 6.1, liveness**: the recorded pid in `/proc` (with cmdline and start time), never the socket file; a
   missing `SessionEnd` is the orphan signal.
5. **Section 6.1, transcripts**: find by `session_id` glob across all project directories; candidate transcripts for a
   role by scanning for `customTitle`; resume by id, never by name (forks and re-runs duplicate names).
6. **Section 9.5**: unchanged. The inbox question (M0c) stays open until items c and l run.
