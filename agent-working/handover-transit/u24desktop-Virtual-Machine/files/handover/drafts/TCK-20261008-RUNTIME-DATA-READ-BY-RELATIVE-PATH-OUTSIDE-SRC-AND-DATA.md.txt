# TCK-20261008-RUNTIME-DATA-READ-BY-RELATIVE-PATH-OUTSIDE-SRC-AND-DATA

## Title
Runtime modules read configuration and registry files outside `src/` and `data/` by relative path (`Path(__file__)` parents or cwd), so a packaged runtime (the backend image) cannot find them.

## Status
OPEN

## Tier
standard

## Type
refactor

## Priority
P3

## Request Summary
This comes from codebase-planner's handoff (#452, `docs/plans/codebase_health/handoffs/handoff_to_rpg.md`, section "Update 2026-10-08"). rpg-planner answered on #452: option (1) now (the Dockerfile copies `config/` and `docs/engine/capability_registry.yaml`) and option (2) later (this ticket).

## Scope
Move runtime-read data into `data/` or package data and read it through `importlib.resources` (or one resolver), with no repo-relative parent walks:
1. `src/engine/kernel.py:248` and `src/simulation_quality/worker.py:67`: `config/simulation_quality/*.yaml` (cwd-relative).
2. `src/rendering/grading.py:33`: `config/rendering/grade_thresholds.toml`.
3. `src/engine/capability.py:8`: `docs/engine/capability_registry.yaml`. A doc file used as runtime data. Decide whether the registry moves to `data/`, with the doc linking to it.

Afterwards, the Dockerfile's extra copies from option (1) can be removed. That is codebase's file, so tell codebase-planner.

## Out of Scope
- Dev-time readers: the content validator's test lookups, the agent-ops dashboard and the lab workflows.

## Acceptance Criteria
- No runtime module under `src/` resolves a file outside `src/` and `data/` by a repo-relative path. A test greps for or imports each one.
- Behaviour is identical: the digests are equal before and after.
