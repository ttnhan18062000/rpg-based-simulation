# Draft edit — `docs/plans/rpg_design_roadmap/rpg_implementer_lane_split.md`

Author: `rpg-planner` (owner of that document), 2026-10-05.
To be applied **verbatim** by whichever implementer's batch carries it. Apply once; if both lanes
pick it up, the second one drops it.

## Why

Three `src/engine/*.py` files are named by tickets now being dispatched and are listed in **neither**
lane's `src/engine/{...}` enumeration and **not** on the contested surface: `tactical.py`,
`world_dynamics.py`, `checkpoint.py`. The lane doc's own §2 enumerations are explicit lists, not
prefixes, so an unlisted `src/engine/` file has no owner and every dispatch touching it needs an
ad-hoc ruling. §5's instruction is to correct the document rather than decide ad hoc, so this
corrects it.

Ruling, with the reason in each case:

- **`src/engine/tactical.py` → Lane A.** It is the immediate-execution half of the
  Strategic/Tactical Rule — it turns an agent's decided objective into movement and attacks. The
  Bible chapter it answers to is 02/04, and its parity entries are in `combat_movement.yaml` and
  `strategic_cognition.yaml`, both Lane A's.
- **`src/engine/world_dynamics.py` → Lane B.** It is the world-evolution tick block (death-triggered
  regional trauma, seasonal pressure). Bible chapter 05, parity `world_dynamics.yaml`, both Lane B's.
- **`src/engine/checkpoint.py` → contested (§3).** `CanonicalStateHasher` is the determinism
  instrument both lanes measure with, and it sits beside the authoritative mutation path already
  listed in §3. It gets a claim, not a boundary.
