# Draft: launcher relaunch fixes (found while relaunching the live sessions, 2026-10-07)

Author: agent-working-designer. Draft only; the owner decides what becomes a ticket, and the
implementer commits. Owned paths: `tools/sessions/**`, `registries/session_roles.yaml`,
`docs/guidelines/session_roles/**` (all agent-working domain).

## Evidence (what happened on 2026-10-07)

1. **Transcript lookup ignores `legacy_session_name`.** `tools/sessions/launch.py` (~line 194-202)
   finds a role's earlier transcripts only where `customTitle == <instance id>`. The live seats were
   titled `world-rule-catalog-design`, `rpg-feature-planning`, `test-architecture-reviewer` and
   `test-architecture-implementer`, so `launch.py rpg-planner --dry-run` reported 0 candidates and
   called a live seat ORPHANED. The registry already records each legacy name in
   `identity.legacy_session_name`; `resolve.py` already uses it for resolution.
2. **Handover notes are read from the MAIN checkout** (`handover_base(root)`), not the role's
   worktree. Two sessions copied notes into `rpg/.claude/handover/` on my instruction, and the
   launcher still reported "no handover note yet: a stub will be created". The role card / launcher
   help never states this.
3. **Stale recorded worktree and branch.** `rpg-planner` instance state recorded
   `m2-idea43-temporal-note` on `world-definition-correctness-batch`, so a default launch would have
   run `git worktree add .../rpg world-definition-correctness-batch` (a spent branch). Self-heal from
   the role's recorded branch is unsafe once that branch has merged.
4. **Two instances of one role and the writer lease.** `session_start_hook.py` (~line 147-151) calls
   `take_lease(..., instance_id, ...)` when `wt.writer == role.role`. The second instance
   (`rpg-implementer-2`) has a different id from the holder (`rpg-implementer`), so `take_lease`
   raises `LeaseRefused` and the hook only appends a note, "WRITER LEASE NOT TAKEN". Not fatal, but
   it prints a warning on every second-instance start, and the lease on the shared `rpg` worktree
   is meaningless when both implementers write only in per-piece worktrees.
5. **`rpg-implementer-1` is not a valid name.** Instance ids are `<role>`, `<role>-2` ..
   `<role>-N` (`resolve.py::instance_ids`). The owner asked for `-1`/`-2` naming; I recommend NOT
   adding an alias (it would split the first instance's history and transcript lookup).

## Proposed changes (smallest first)

**A. `launch.py` transcript candidates also match `legacy_session_name`** (item 1). Test: a role
whose only transcript has `customTitle` = its legacy name is listed as a candidate, and
`default_action` can suggest `resume`. Add a regression test in `tests/tools/`.

**B. Say where the handover note is read from** (item 2). One line in the dry-run output
(`handover note: <absolute path>`; `none` stays as is) and one sentence in
`docs/guides/` session-roles launcher usage. No behaviour change.

**C. Do not self-heal from a recorded branch that is already merged** (item 3). Before
`git worktree add <path> <branch>`, check whether `<branch>` is an ancestor of `origin/main`; if so,
print "recorded branch `<b>` is merged; create the worktree from origin/main yourself" and stop,
as the "no branch recorded" case already does.

**D. Second instance and the writer lease** (item 4). Either (i) skip the lease when the starting
instance id is not the role's first instance, or (ii) keep the note but reword it so it names the
cause ("writer lease is held by the first instance; instances write only in per-piece worktrees").
Recommend (i). Decide with the owner whether the writer lease should exist at all for a worktree
used only as a launch cwd.

**E. Card wording: two instances never write the same worktree.** `rpg-implementer` asked for the
rule; `registries/session_roles.yaml` implies it (one writer slot per worktree) but no card says it.
Implementer card, current text (docs/guidelines/session_roles/functions/implementer.md, line 14):

> Function: implementer. Sole writer to your worktree. One PR per batch; ...

Proposed:

> Function: implementer. Sole writer to your worktree; with two instances, each writes only in its own per-piece worktree off origin/main. One PR per batch; ...

Cost: about 20 tokens. The cards sit at the 400-token cap (the planner card needed a trim today), so
the implementer must regenerate the cards and re-run `tests/tools/test_session_cards.py`; if over the
cap, shorten to "Sole writer to your worktree; two instances never share one." (about 10 tokens).
Do not edit it on PR #400's branch until the implementer has applied the planner-card trim, to avoid a
conflict in the same generated cards.

## Not proposed

- A `-1` alias for the first instance (item 5).
- Changing the one-writer-per-worktree model. The seats already work around it with per-piece
  worktrees; the registry comment says designers and planners hand drafts and the implementer
  commits. That is a process question for the owner.

## Out of scope

The dirty main checkout (317 staged/unstaged entries, 100 commits behind origin/main) and pruning
old worktrees: both are the owner's decisions.
