## STANDING DESIGN DIRECTION (owner, 2026-10-08): apply to EVERY domain, not just food
Food and survival are one small slice of the foundation. The owner wants the ideas from today used as the
default lens for later decisions everywhere:
1. COMMON SENSE, MANY WAYS: a need or goal has the several ordinary ways real people or creatures would use
   (eat: gather, hunt, raw, cook, buy, receive). Never let one missing system (e.g. a shop) be the only path.
   When a rule names one way, ask "what else would a person plausibly do?"
2. EVERY WAY HAS A REAL COST; NOTHING IS FREE: no engine charity; things enter and leave by real causes
   (conservation, provenance).
3. THE WORLD DECIDES, NOT A TARGET: amounts come from the fiction (land, kind, place), never fitted to an
   acceptance number.
4. FOUNDATION, NOT PERFECTION: a light, plausible balance pass is fine when outcomes are implausibly harsh;
   record before and after; fine tuning waits for features (decision 33).
5. SUBJECTS NOTICE AND DECIDE: a meaningful change next to a subject (a hostile in reach, danger, a dry
   source) gets a decision, not a blind continuation and not a freeze (decision 32, held-task re-decisions).
6. PLACES FIT WHO LIVES THERE: settled land and its near surroundings are livable; lethal danger sits deeper
   (decision 30).
8. EVERY LIVING KIND (decision 42, owner 2026-10-09): an entity is every living creature, not just humans.
   Rules about bodies, needs, noticing/deciding and where a kind lives cover animals by default, sized by the
   kind's profile; people-only rules (money, wages, crafts) say so and why. Specs get a non-people-kind arm;
   ask lanes to report animal kinds in measurements.
9. ROLES FROM PROPERTIES, NEVER LABELS (decision 46, owner 2026-10-09): no hardcoded roles ("a rabbit must be
   prey"). Kinds declare properties (size, power/danger, wits, diet, edibility, ...); hunting, fleeing and any
   other role follow from those plus the situation. A tag is OK only when it IS the property (D43 "keeps coin and
   trades"). Every spec gets a derivation arm proving the behaviour comes from properties, not a flag.
10. GENERIC NOW, SPECIFIC LATER (decision 50, owner 2026-10-09): the foundation uses generic archetypes ("small
   plant-eater", "medium meat-eater") and coarse bands (small/medium/large); never named real species or exact
   figures in decisions, specs or content until the foundation is hardened.
7. REGISTER EVERYTHING: catalog family, memo row, roadmap §10, scenario bank, mechanisms.yaml pointer (via
   the lane whose code touches it), and the REGISTRY regen.
Offer these as options with a recommendation; the owner still confirms each new ruling.

## Process lessons (what made this decision set survive)
- **Measure the artifact, don't reason about it.** The 24-world static geometry sweep (seconds, no simulation)
  overturned the planner's conclusions three times: the "nested" premise, "overlap is rare", and the 4-region
  subset that hid a nested town.
- **Every measured figure carries its BASE commit.** Verify ancestry with `git merge-base --is-ancestor` before
  stating "before/after fix X". A relayed base label was wrong once.
- **Quote a SHA only from command output after the last amend or rebase.**
- **Any relayed scope change is flagged, never silent,** whether it narrows or widens an owner decision.
- **After a registry edit:** run tests/unit/tools, regenerate every `make mechanism-*-view`, and run
  `make mechanism-registry-validate`.
- **docs/REGISTRY.yaml:** the post-merge hook regenerates it. Verify against a clean `git archive HEAD` export
  with `tools/generate_registry.py --root <clean> --check`. A conflicting PR runs no CI, so "nothing failing"
  is not green.
- **PR body:** `tools/delivery/pr_render.py --scope world --theme … --why …` for a branch that closes no
  ticket; fill the Review notes and Tests line by hand; no attribution footer.
