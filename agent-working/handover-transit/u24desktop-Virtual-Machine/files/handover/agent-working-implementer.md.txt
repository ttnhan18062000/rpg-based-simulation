## Facts learned
- **CI triage rule that bit me:** `Tools · f–z` failed on `docs/REGISTRY.yaml` drift after adding tickets. After any ticket add/move run `python3 tools/generate_registry.py --output docs/REGISTRY.yaml` then `--check`.
- `gh` is 2.45: `gh pr checks` has no `--json`; text is `name\tbucket\tduration\turl`, exits 1 while anything fails/pends. `gh api --paginate` emits concatenated JSON, so paginate by hand. `gh pr edit` fails: use `gh api -X PATCH repos/{owner}/{repo}/pulls/N -f title=... -F body=@file`.
- `pr_status.py` is now complete-context (check runs + statuses + `gh pr checks` cross-check) but `gh pr checks` stays ground truth for humans; this repo has no required checks, so that branch is test-only.
- A closed ticket needs `status: historical`/`phase: done` in frontmatter, `## Status DONE`, move to `done/`, `record_hand_orchestrated_closure.py` (appends the working_log row; do not also call `append_working_log_row`), `done_checker_static.py --ticket-id X --tier T` (precheck FAILs after the move are expected; the finalize lines must PASS), standard tier also needs `plan.md`/`investigation.md`/`test_plan.md` under `stored_artifacts/<ID>/`, then `rm -rf data/runs/* reports/release_proof/*`, `make knowledge-index-update` if docs changed, `graphify update .` if Python changed.
- Terminal statuses are extractor-derived: a raw `record_run.py --data '{...,"final_status":"X"}'` line in `implement-ticket.js` registers as a `bypass` status, so `terminal-statuses.yaml`, the regenerated `rendered/claude-adapter.yaml` (`render_claude_adapter`), sampler `_GATE_FAILURE_STATUSES`, schema doc and four pinned counts (now 18) must move together.
- Branch switch with a modified tracked shard aborts: `cp --parents` the shard aside, `git checkout --`, `git cherry-pick --quit` if a failed pick is pending, switch, pick, copy back. A hook-appended `tools.jsonl` that was discarded loses only tool-usage rows.
- `git stash` with paths backgrounded a 6-minute pytest; never chain stash around long runs. Foreground `sleep` is blocked; poll with an until-loop and a positive completion signal.
- MCP `search_docs` index path is now repo-root anchored; the index is per-worktree and a fresh worktree has none (`search_docs` returns `[]`); `tools/prune_worktree_indexes.py` (dry run default) reclaims idle worktrees' indexes: 474M in 3 other worktrees on 2026-10-04.
