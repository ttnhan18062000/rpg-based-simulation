Before dispatching a ticket to an implementer session, **push the ticket file** to the branch they
will work from. Verify it is actually on the remote (`git ls-tree -r origin/<branch> --name-only |
grep <TICKET-ID>`), not merely committed locally.

**Why:** a dispatch message is a summary; the ticket is the artifact. Confirmed live 2026-09-24 on
the semantic-control-plane track. Two scoping commits (an M1 mapping ticket and a TERR-01 citation
hotfix) were committed locally and never pushed. The implementer, working from the `SendMessage`
dispatch alone:

- **reconstructed the hotfix under a different ID** (`TCK-20260923-TERR01-CITATION-FIX` instead of
  `TCK-20260923-TERR01-STALE-JURISDICTION-CITATION`), leaving an orphaned unimplemented duplicate in
  `tickets/todos/` alongside the closed one in `tickets/done/` — the duplicate shape
  [[feedback_hand_orchestration_gate_patterns]] already warns about, arriving by a new route;
- **started M1 with no ticket file on its branch at all**, working from a message that carried a
  fraction of the ticket's content. The file held a pre-verified candidate-mechanism table (including
  a binding trap: a plausible service with zero real callers), a CONFLICTING-vs-PARTIAL litmus test
  with precedents, 8 numbered ACs, and a Findings section. None of that survives summarization, and
  it is exactly the part that took the scoping work to produce.

Nothing errored. The implementer reported clean progress both times, because a reconstructed ticket
looks like a real one from the inside. Only a `git ls-tree` on the remote revealed it.

**How to apply:**
- Dispatch order: commit → **push** → verify on remote → `SendMessage`. Never commit → dispatch.
- Name the exact branch and the exact ticket path in the dispatch, so a missing file is noticed.
- Tell the implementer: if the named ticket file isn't on its branch, stop and ask — don't
  reconstruct from the message.
- When a peer reports closing a ticket under an ID you don't recognise, treat the rename as a signal
  the file was missing, not as a cosmetic choice, and check for an orphaned duplicate in
  `tickets/todos/`.
- Pushing onto an open PR's branch re-triggers CI — see
  [[feedback_no_monitoring_commits_while_polling_ci]].
