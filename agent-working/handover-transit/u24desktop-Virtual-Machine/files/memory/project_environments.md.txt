Two environments run this project:

| Machine | Venv path |
|---|---|
| u24desktop (primary) | `.venv/bin/python3` (project-local) |
| vboxuser | `/home/vboxuser/Work/venv/bin/python3` |

**Why:** Different machine setups; `start_search_mcp.sh` and Makefile `knowledge-index`/`knowledge-index-update`/`eval-search`/`mcp-server-test` targets all use a priority-ordered fallback list covering both.

**CPU-only PyTorch:** Both environments use `torch+cpu` only — no GPU/CUDA. Install with:
```
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e ".[knowledge]" --extra-index-url https://download.pytorch.org/whl/cpu
```

**SSL cert fix for HuggingFace:** Python's default SSL bundle fails for huggingface.co on these machines. Fix:
```
SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt SSL_CERT_DIR=/etc/ssl/certs
```
This is baked into the Makefile `knowledge-index` targets so it's transparent.

**How to apply:** When setting up a new environment or debugging knowledge-index failures, check venv path and SSL cert env vars first.

**Bare `python3` on u24desktop lacks pydantic (2026-08-18):** `/usr/bin/python3` (what plain `python3` on PATH resolves to) has no `pydantic` installed — only `.venv/bin/python3` does. This breaks any test that does `subprocess.Popen(["python3", "-m", "src", "serve", ...])` with the literal string `"python3"` instead of `sys.executable` — the spawned server process crashes on import, causing `requests.exceptions.ConnectionError` in the test. Confirmed via `.github/workflows/test.yml`: real CI uses `actions/setup-python@v5` + `pip install -r requirements.txt`, so `python3` resolves correctly there — this is a local-sandbox-only artifact, not a real regression. When a subprocess-spawning test fails this way: (1) confirm the file is untouched by your diff via `git status`, (2) confirm bare `python3 -c "import pydantic"` fails and `.venv/bin/python3 -c "import pydantic"` succeeds, (3) confirm CI's setup via the workflow file, (4) deselect with `--deselect` (not a blanket file skip) and document the reasoning — this is a known, recurring, pre-existing quirk on this machine, not something to "fix" by editing the test.
