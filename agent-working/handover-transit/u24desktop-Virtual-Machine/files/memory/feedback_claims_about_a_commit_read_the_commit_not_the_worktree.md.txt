On 2026-10-05 I told a peer its finding was false by grepping `git show --stat` for "done_checker_static" (which also matched the test file) and by reading the working tree, which held the implementer's later uncommitted fix. The peer was right; I had to retract. The peer had made the mirror-image mistake (working tree, and `head -12` on a 15-file stat).

**Why:** the shared worktree's checked-out state moves under me (the implementer is the only git writer), so the working tree answers a different question than "what is in commit X".

**How to apply:** to claim what a commit changed, run `git show <sha>:<exact path>` and `git show <sha> --name-only` matched on the full path with `grep -x` or the exact filename, never a substring that a test file can also match, and never a truncated list.
