The **agent-monitoring retro** (`/agent-monitoring-retro`, and the `retro-loop-enforcement` hook that
nudges "N implement-ticket runs DONE since the last dated report, threshold 5") is **not this session's
boundary**. User, 2026-10-02: "ignore the monitoring retro, it's not your boundary."

Do not run it, do not offer it, and do not list it as an open item in a handover or a status summary.
The agent-monitoring/agent-tooling lane owns it — see
[[feedback_report_agent_process_issues_to_agent_working_design]].

**Why:** the `PostToolUse` hook fires the nudge on ordinary file reads, so it surfaces constantly and
looks like an outstanding task addressed to whoever sees it. It isn't. I carried it as a pending user
decision across a `/clear` boundary and then raised it three times in one session before being told to
stop — each mention cost the user a dismissal and crowded out the items that *were* mine.

**How to apply:** treat the retro hook's output as background noise, the same as the `sidecar-check` and
`context-search` nudges that fire on unrelated edits. A monitoring-cadence hook firing is not a
work assignment. If the retro genuinely needs running, its owner's user will ask. Distinct from the
**epic-staleness** check, which the user *did* choose to act on (2026-10-02) and which produced a real
finding — so don't over-generalise this to every cadence nudge.
