Adding a terminal status (done for `WORKFLOW_ERROR`, 2026-10-03, #300) touches `agent-working/agent-orchestration/terminal-statuses.yaml`, the generated `rendered/claude-adapter.yaml`, `docs/agent-monitoring/schema.md`, six count pins (`test_terminal_status_extractor.py`, `test_terminal_status_schema.py`, `test_generator_containment.py`, `tests/agent_orchestration/test_contract_structure.py`) and `tools/agent_replay/sampler.py::_GATE_FAILURE_STATUSES` (a test now fails when a contract status is unclassified). No intentional-divergences entry is needed when the contract is updated in the same change.

**Why:** I first ran only the adapter test directory and missed the `tests/agent_orchestration` pin; the sampler silently labelled seven failure statuses as success.

**How to apply:** run the 46 test files naming `implement-ticket.js` plus `tests/agent_orchestration*` and `tests/agent_replay` for any status or script change. See [[feedback-push-to-open-pr-not-new-stacked-pr]] for PR handling.

Worktree traps: `git switch` aborts when hook-appended tracked `*.tools.jsonl` shards differ between branches; copy them aside with `cp --parents`, `git checkout --` them, switch, copy back, never commit them. Do not add a second worktree under `/tmp` (the disk hit ~100% and the checkout failed; tests asserting no `tmp` in a path also fail there).
