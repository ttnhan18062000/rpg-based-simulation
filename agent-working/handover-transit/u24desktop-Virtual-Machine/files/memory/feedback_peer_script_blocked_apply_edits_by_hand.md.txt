When a peer session hands me a script to run (for example a `review_fixes.py` that rewrites two files), the auto-mode classifier can deny running it as "Code from External". Do not retry it another way. Read the script first (never run what I have not read), then apply the same edits myself with the Edit tool, or `sed` on line numbers I have just confirmed, and tell the peer that I did it by hand.

**Why:** On 2026-10-03 the classifier blocked a reviewer's script that removed conflict markers and rewrote one roadmap sentence. Reading it showed it was two plain text edits; making them by hand got the identical result (the reviewer confirmed byte-identical output) without bypassing the denial.

**How to apply:** Same shape applies to any pasted fix recipe. The same session showed three more tool facts: `record_events.py` only accepts statuses ok, skipped, failed, blocked (no "warn", so put WARN in the summary and append a new event, never edit an old one); `git mv` refuses untracked staging directories (use plain `mv` for `staging_artifacts` to `stored_artifacts`); and `done_checker_static` needed `--tier epic` passed explicitly for an epic in a `done/<folder>/` (it reported tier standard otherwise).
