While a PR is open and you are waiting on CI, **do not commit trailing
`agent-monitoring/data/**/tools.jsonl` writes**. Let them accumulate uncommitted and land them in
one commit after CI settles and you're ready to merge.

**Why:** checking CI is itself a tool call, so the `PostToolUse` hook writes a `tools.jsonl` row
for it. Committing that row and pushing retriggers the full CI suite, which invalidates the run
you were just checking — a self-perpetuating loop where the act of observing CI destroys the
result being observed. Confirmed live 2026-09-09 on PR #149: four consecutive commits on the
branch were all `agent-monitoring: trailing tools.jsonl write from CI-monitoring activity`, the
peer session reported "fully green" twice off runs that its own polling had already superseded,
and 4+ full suite runs burned for zero code change. The peer initially diagnosed it as flaky CI;
the real cause was structural.

This does **not** conflict with CLAUDE.md's "always stage `agent-monitoring/` in every commit"
rule — that rule's intent is "don't leave `agent-monitoring/` as an unstaged modification in your
work commits," not "create a new commit per CI poll on an open branch."

**How to apply:**
- When polling CI, check the run tied to the branch's **current HEAD SHA**, not "the most recent
  run I saw go green." If HEAD moved after a run started, that run is stale by definition —
  `gh pr checks` will happily show you a superseded run's results.
- Before reporting "CI is green" to the user or a peer, confirm the run's head SHA matches
  `git rev-parse origin/<branch>`.
- A single job failing while an adjacent run passed, with only a monitoring-log commit between
  them, is a strong signal of this loop rather than a real regression — but still reproduce the
  failing job's command locally before concluding flake (CLAUDE.md's CI Failure Triage rule
  applies; never conclude from the job name alone).
- Related: [[feedback_sidecar_shape_and_index_staleness]] covers the other direction of this same
  hook's behavior (missing sidecar -> zeroed cost_proxy_score).
