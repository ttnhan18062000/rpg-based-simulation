The shared `/mnt/data/Working/rpg-based-simulation/.venv` (and the `/home/u24desktop/...` one) has no `ast-grep` or `ruff`, so `tests/codebase` make-target tests fail locally with "ast-grep not found" (not a timeout). `/usr/bin/sg` is shadow-utils, not ast-grep. CI's `tools-a-e` job runs `tests/codebase` after a FULL `uv sync --locked --no-install-project` (lint group included); only the fast jobs that skip codebase tests use `--no-group lint`.

**Why:** plain `uv sync` fails here with `invalid peer certificate ... CaUsedAsEndEntity` when it needs to fetch `ast-grep-cli`; `--native-tls` works. Found 2026-10-06 while measuring the two code-health make-target tests.

**How to apply:** `UV_PROJECT_ENVIRONMENT=<scratchpad>/cienv uv sync --locked --no-install-project --native-tls`, then put `<cienv>/bin` first on PATH (the make targets call `python3 -m ...` and the tools by name). Never install into the shared venv. Timings from this VM are not idle (load ~2-3, many sessions); say so. Related: [[feedback_ci_repro_never_from_tmp]].
