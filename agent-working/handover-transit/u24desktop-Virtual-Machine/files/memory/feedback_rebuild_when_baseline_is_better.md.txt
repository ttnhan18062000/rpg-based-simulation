Don't default to "consolidate/reuse the existing thing" just because it exists. If real investigation finds
the existing thing has a genuine defect (not just disorganization), and a freshly-built replacement — using
real technique/theory, not guesswork — would be a much better baseline, propose the rebuild, not a migration
of the flawed original into a tidier shape.

**Why:** while investigating `docs/plans/idea_hud_color_asset_system.md`'s frontend color-constant sprawl
(9 tables across 7 files), the first draft proposed consolidating the ~200 existing hex values into one
source-of-truth file, preserving their current values. But the investigation had already found a real
defect *in the values themselves* — `COMBAT` vs `ALERT` computed to a WCAG contrast ratio of 1.00
(functionally identical), a real accessibility failure, not a disorganization problem. Consolidating those
exact values into one file would have centralized a broken palette, not fixed it. The user's correction:
*"we don't need to always reuse the existing, if the new baseline is much better, we can start implementing
everything from scratch again, it worth the effort."* The doc was revised to propose a newly-generated
palette (informed by the real WCAG/ColorBrewer/colorblind-simulation research already done) as the primary
recommendation, with file consolidation as a secondary, still-worthwhile architectural fix that happens
either way once real values exist to put in it.

**How to apply:** When investigation surfaces both (a) genuine disorganization/duplication AND (b) a real
defect in the current values/design themselves (not just where they live), don't default to a
migration/consolidation framing that quietly preserves the defect. Weigh a fresh rebuild on its own merits —
if it's evidence-backed and clearly better, propose it as the primary path, with reuse/consolidation as the
fallback or a secondary structural step, not the default framing. This isn't a blanket "always rebuild"
rule — it's specifically for cases where reuse would mean preserving something already shown to be broken,
not merely something that could be tidier.
