When the user said "why you keep asking me for permission, I allowed them" and pasted the prompt, the cause was the PreToolUse `session-roles guard`: "uncertain classification: unparseable command containing an authority-class word". It fires on chained commands (`;`, `&&`), command substitution, variables used as the program, `git -C`, and `setsid` with computed arguments, and the user has to confirm each one even though the underlying actions are allowed.

**Why:** the guard cannot prove a chained command stays inside the worktree or isn't a git operation, so it asks. The user reads that as me asking for permission.

**How to apply:** one plain command per Bash call (a multi-line `git commit -m "..."` on its own is fine); put anything scripted into a file with the Write tool and run the file; no `$(...)`. Do not edit `.claude/settings.json` to quiet it; an allow rule there is the user's change. See [[project-hook-and-permission-rule-traps]] and [[feedback-pr-creation-needs-direct-user-confirmation]] (push/PR after a complete batch is already standing permission; merge is not).
