When a peer supplies **verbatim** text to apply to docs (catalog edits, Bible blocks, rule wording),
push it as a committed file (e.g. `staging_artifacts/<TCK>/catalog_edits*.md`) with anchor/replacement
blocks fenced, the substitution rules stated, and a "stop and report the delta, don't paraphrase"
instruction. Never relay it as prose in a `SendMessage`.

**Why:** `rpg-implementer` correctly **refused** to apply a batch I summarised in a message — whole-block
verbatim edits cannot be reconstructed from a summary, and guessing would corrupt rule text. Pushing the
exact strings as a file unblocked it immediately. `world-rule-catalog-design` has since adopted this as
its default for all catalog text (2026-10-01).

**How to apply:**
- Include a "transcription notes" section: message-level `\"` escaping is *not* literal content.
- **Verify every anchor is unique in its own file before replacing.** An owner-supplied anchor
  (`- **Result: covered.**`) occurred **8 times** in one file; another near-identical outcome list
  appeared in two different files. Anchor on a file-unique neighbouring phrase instead.
- Doc edits that assert new behaviour land **in the same commit as the code that makes them true**,
  never ahead of it.
- Keep a running table of every location touched across batches, so the footprint is auditable from one
  file rather than several transcripts.
