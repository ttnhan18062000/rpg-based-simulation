On 2026-10-03, after `git merge --ff-only origin/main` across the PR #289 `agent-working/` root move, the main checkout had `HEAD == origin/main` but the index and working tree were still the old layout (no `agent-working/`, ~8000 phantom staged changes). Cause not found. A pre-push hook listing a wall of "A agent-monitoring/..." paths was the symptom.

**Why:** acting on a stale tree would read pre-move files and could commit the phantom state.

**How to apply:** after any ff over a big move run `git status --short | wc -l` and `ls` the new root. If it is huge, back up real uncommitted work first (diff of the few genuinely modified tracked files plus untracked shards), then `git reset --hard HEAD`, then re-apply appended shard rows only where the new-path file is a strict prefix of the backup (never overwrite a tracked file with unrelated content). Do all of this before concluding anything from that checkout.
