When hand-orchestrating or running the implement-ticket/implement-epic pipelines and a real
structural gap in the workflow tooling itself is found (not a one-off ticket mistake, but something
the JS/skill orchestration should have covered and didn't), file a real ticket for the tooling gap
— don't just quietly work around it in the moment and move on.

**Why:** User explicitly asked for this after I found and hand-patched
`docs/plans/rpg_design_roadmap/rpg_design_roadmap.md`'s stale M1 tracking note (implement-epic.js's
folder mode has no mechanism to keep a batch's own roadmap doc in sync as child tickets complete) —
filed as [[TCK-20260826-IMPLEMENT-EPIC-ROADMAP-DOC-STALENESS-GAP]]. This mirrors an existing repo
pattern already established by prior tickets like
`TCK-20260807-CURRENT-RUN-SIDECAR-HAND-ORCHESTRATION-GAP` and
`TCK-20260807-SEARCH-BEFORE-GREP-OBSISO-EPIC-GAP` — both filed after a real hand-orchestration gap
was found live, rather than silently absorbed.

**How to apply:** During any ticket/epic pipeline run, if I notice the JS/skill/agent orchestration
itself missed a step it structurally should have covered (not just "this one ticket's docs were
incomplete" — that's normal Document-Update scope) — file a `layer: ai` standard-tier ticket in
`tickets/todos/` describing the gap, citing the concrete instance that surfaced it, and proposing
(not necessarily implementing immediately) a fix. Don't fold the tooling fix into the ticket that
happened to surface it — keep them separate, the way the M1 roadmap staleness fix (a narrow doc
edit, committed directly) was kept separate from the new tooling ticket describing the systemic gap.
