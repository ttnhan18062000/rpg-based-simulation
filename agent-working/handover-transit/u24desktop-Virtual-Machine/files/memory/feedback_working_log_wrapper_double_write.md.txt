Never call `append_working_log_row()` directly AND
`tools/agent-monitoring/record_hand_orchestrated_closure.py` for the same ticket closure — the
wrapper already appends its own `tickets/working_log.csv` row from its `--title`/`--log-summary`
args. Calling both creates a duplicate `(ticket_id, title)` pair that trips the real-corpus
duplicate-ratchet CI tests (`tests/tools/test_working_log_duplicate_check.py`,
`test_working_log_content_duplicate_check.py`).

**Why:** confirmed live 2026-09-14 on `TCK-20260914-LAIR-WORLD-BOSS-MATURITY-GATE-REACHABILITY` —
manually called `append_working_log_row()` during closure, then separately ran
`record_hand_orchestrated_closure.py`, which appended a second row for the same ticket. CI's
`API / tools / logging` job failed on the resulting duplicate. The wrapper's own module docstring
already states this exact warning explicitly ("do NOT also call append_working_log_row separately
when using this wrapper, or the ticket will get a duplicate working_log entry") — missed it despite
reading the script to check its signature.

**How to apply:** when closing a hand-orchestrated ticket, pick exactly one path — either call
`append_working_log_row()` directly, or pass `--title`/`--log-summary` to
`record_hand_orchestrated_closure.py` and let it write the row — never both. Before invoking either,
grep the other for whether it's already being handled. If a duplicate does slip through anyway, fix
it by removing the redundant row (root cause), never by adjusting the ratchet ceiling test itself.
