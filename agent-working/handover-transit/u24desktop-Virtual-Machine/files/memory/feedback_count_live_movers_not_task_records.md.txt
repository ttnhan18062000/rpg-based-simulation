Twice in one session a metric counted what exists instead of what runs, and the headline had to be corrected:
- Attack verdict streaks looked "bounded" because a task that never re-dispatches emits no verdicts; following the task showed an 851-tick hold.
- "10 of 21 held moves" counted task records whose mover was a corpse (a dead or inactive entity keeps its stale task and `scheduler.py` never dispatches it again). The live harm was four instances (986, 30, 20 ticks and one circling a live target).

**Why:** a measurement over a population that includes inert members overstates the defect, and a planner built a ruling on the first number.

**How to apply:** before headlining a count, name the population and check each member is live (`lifecycle.active and combat.alive`) and actually dispatched (instrument the dispatcher, e.g. count `tracked_move_complete` calls per entity). Report a corrected headline to the planner the moment it shrinks. Compare before/after arms in one tree with a `legacy` monkeypatch in the probe.
