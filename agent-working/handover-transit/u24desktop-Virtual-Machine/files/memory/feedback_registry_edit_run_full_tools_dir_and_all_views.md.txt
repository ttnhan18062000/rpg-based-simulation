After editing `registries/mechanisms.yaml`, do two things before handing the change over:
- Regenerate **every** derived view, not just the `mechanism_*` ones. That includes `make territory-control-view` and `make cross-domain-management-view`.
- Run the **whole** `tests/unit/tools` directory, which is what CI runs. Do not run a `-k "mechanism or semantic or rule"` subset.

**Why:** on 2026-10-03 my regional_sovereignty change (`ab69c175c`) passed my filtered 326-test run. It then failed CI on PR #292, because `territory_control_management_view.md` and `cross_domain_management_view.md` had gone stale. The peer had re-run my exact narrower command, so both checks shared the same blind spot.

**How to apply:**
- Use `pytest tests/unit/tools`, the full directory (about 493 tests).
- When handing over the verification command, give the CI-equivalent one, not a narrower one.
