When dispatching a batch to a lane, check each cited artifact is **reachable from `origin/main`**,
not merely that it exists and says the right thing. On 2026-10-05 I dispatched Lane A a four-ticket
batch citing `docs/plans/rpg_design_roadmap/rpg_implementer_lane_split.md` and
`TCK-20261005-BRAVERY-QUARTILE-GUARD-RED-ON-MAIN-UNOWNED` — both existed only in the *other* lane's
unmerged PR (#335), so Lane A could not start those two items from a branch cut from `origin/main`.
`rpg-implementer` caught it and resequenced itself correctly.

**Why:** I verified the tickets' *content* against the lane split and skipped the reachability check
entirely. In a two-lane setup the other lane's open PR is invisible to the lane you are dispatching —
a cross-lane citation is only usable once that PR merges, and merging is the user's call.

**How to apply:** at dispatch time, for every file path you cite, run
`git cat-file -e origin/main:<path>` (or `git log origin/main -1 -- <path>`). If it is absent, either
sequence that item behind the other lane's merge and say so in the dispatch, or hand the implementer
the content directly. Same failure family as [[feedback_fetch_before_recommending_a_ticket]] and
[[feedback_check_ancestry_before_citing_pr_lines]] — findings and artifacts are branch-anchored.
