Since #329 `python3 -m codebase.health check` is a blocking CI job. Each function has a ceiling in `codebase/baselines/code_health_exceptions.jsonl`, and a function fails when it grows past it (3 of my edits failed on #362: `ActionRoutingPhase.route` complexity 103 over 96 and length 253 over 240, `ActionRouter.execute_action` length 110 over 97). The failure line names the function, rule and ceiling in the job log (`gh run view <run> --job <id> --log-failed`).

**Why:** the two functions were already at their ceilings, so any inline condition, comprehension or comment block pushed them over, even with no new class of problem.

**How to apply:** put new logic in small module-level (or `@staticmethod`) helpers with annotated arguments and no function-local imports, and move long rationale comments into helper docstrings; measure length with `ast` (`end_lineno - lineno + 1`). `ruff`, `mypy`, `complexipy` and `ast-grep` are not installed in the shared venv (`tests/codebase` fails locally for that only), so CI is the first run: say so in the PR body. Never touch `codebase/baselines/`. Related: [[feedback-new-local-imports-fail-ruff-plc0415-in-ci]].
