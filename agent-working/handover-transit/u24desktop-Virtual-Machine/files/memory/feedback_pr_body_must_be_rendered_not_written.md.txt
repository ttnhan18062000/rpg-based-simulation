**Never hand-write a PR title or body for this repo.** Render it:
`python3 tools/delivery/pr_render.py [--theme "<short what-landed phrase>"]`, paste the hand-written
material into the one hand-filled section (`## Review notes`), then verify with
`pr_render.py --check --pr <N> --theme "<same theme>"` until it prints `matches: True`.

The contract is `docs/guides/delivery_process.md`, mirrored in `.github/pull_request_template.md` and
`tools/delivery/pr_template_spec.json`. Required order: `## What landed` → `## Tickets` (id/tier/title
table) → `## Why` → `## Verification` → `## Review notes` → `Closes: TCK-…`.

**Why:** `CLAUDE.md`'s own "PR Lifecycle" section walks commit → push → `gh pr create` → monitor CI and
**never mentions the renderer or the template**, which is exactly why a hand-written body looks fine
and is non-compliant. Confirmed 2026-09-29 on PR #254: the hand-written body had no `Closes:` line, no
Tickets table and no Gates line — and the missing `Closes:` would have erased the ticket ID from
`main`'s history after the squash merge.

**How to apply:**
- Pass `--theme` on both the render and the `--check`, or `--check` re-renders the default title (the
  ticket's own wrapped `## Title`) and reports a spurious mismatch.
- **Re-render after folding a second ticket into an open PR.** Every generated section goes stale, and
  `Closes:` must name all of them. The layer prefix can change too — the renderer warns
  `scope tie among layers [...]; picked '<x>' (first-discovered)`. Accept its pick; overriding it makes
  `--check` fail permanently.
- A `WARNING: changed ticket file but no commit-subject mention` for a ticket the PR does **not** close
  is informational — the renderer correctly omits it from `## Tickets` and `Closes:`, and
  `--exclude-ticket` is only for commit-subject-discovered IDs.
- **The case that does need `--exclude-ticket`: your own commit subject names a ticket you edited but
  did not close.** Repo convention puts a ticket ID in every commit subject, so a commit that only
  *corrects* an open ticket (a stale status line, a cross-reference) gets that ticket discovered and
  listed under `## What landed` and `## Tickets` — reading as though the PR closed it. Confirmed
  2026-09-29 on PR #258, where a status fix inside an open epic was rendered as a landed ticket.
  Exclude it with a reason saying it stays open:
  `--exclude-ticket <ID> --exclude-reason "Not closed by this PR. <what actually changed>. Still open
  in tickets/todos/."` The reason is written into the body as an HTML comment, so the exclusion is
  recorded rather than silent, and `--check` reads it back from the live PR.
- **Re-render after `origin/main` moves under you.** A stale base makes the renderer report tickets
  from *other* merged PRs as changed-but-unmentioned. Rebase onto current `main` first, then render —
  otherwise the warning list is noise and hides a real one.
- `gh pr edit` fails with a Projects-classic GraphQL error; use
  `gh api --method PATCH 'repos/{owner}/{repo}/pulls/<N>' -F title="..." -F body=@<file>`.
- The repo's PR-body attribution exclusion still applies: no `Co-Authored-By`, session link, or
  tool-attribution line in a PR body. See [[feedback_no_coauthor_footer_in_pr]].
