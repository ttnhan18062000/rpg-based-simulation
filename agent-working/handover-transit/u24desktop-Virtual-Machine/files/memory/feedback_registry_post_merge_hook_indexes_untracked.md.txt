---
name: feedback_registry_post_merge_hook_indexes_untracked
description: "The post-merge REGISTRY.yaml hook scans the WORKING TREE, so it auto-commits entries for untracked local files — check its diff after any ff-merge instead of trusting it."
metadata:
  type: feedback
---

`git merge --ff-only origin/main` fires a post-merge hook that regenerates **and commits**
`docs/REGISTRY.yaml` (`[registry-post-merge]`). The generator scans the **working tree**, not the
index, so any untracked ticket sitting in `tickets/todos/` gets a registry entry — and that entry is
then committed, leaving the branch one commit ahead of `origin/main` describing a ticket that is not
on `origin/main`.

**Why:** hit live 2026-09-30 while syncing after PR #260. A local draft copy of
`TCK-20260930-CONSERVATION-REJECTION-PATH-ASSERTION-GAP` (handed to the implementer to commit on its
own branch, per [[feedback_implementer_owns_all_commits]]) was still untracked in the planning
worktree. The hook indexed it, creating a bogus 22-line registry addition and an unpushed commit that
would have become a `/clear` blocker had it not been checked.

**How to apply:**
- After any `git merge --ff-only origin/main`, run `git rev-parse HEAD origin/main` — two different
  SHAs mean the hook committed something.
- Read `git diff origin/main HEAD -- docs/REGISTRY.yaml` before accepting it. A timestamp-only change
  is noise; new `type: ticket` entries mean it indexed local files.
- Drop it with `git reset --hard origin/main`; `REGISTRY.yaml` regenerates on every close anyway.
- Delete the local draft once the implementer has committed its own copy — the same duplicate hazard
  as [[feedback_hand_orchestration_gate_patterns]], arriving through the registry rather than the
  done-checker.
