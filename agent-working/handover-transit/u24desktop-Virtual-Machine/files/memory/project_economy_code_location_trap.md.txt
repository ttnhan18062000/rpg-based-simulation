`docs/mechanics/03_economic_laws.md` (atomic conservation) maps to **`src/core/conservation.py`**
(`ResourceTransactionResolver.resolve()`, 334 lines, marker `VERIFIED v2: atomic_conservation_law`).
It does **not** map to `src/systems/`, which is where the chapter's framing leads people.

The trap: `src/systems/economy.py` (2 lines), `market.py` (3), `crafting.py` (3) and
`harvest_system.py` (2) are **re-export shims**. The real modules are one level down in
`src/systems/economy_systems/` and still small (`economy.py` 56, `market.py` 84). The shim/real split
is not visible from the import path — `from src.systems.market import MarketSystem` looks like the
real thing.

**Why:** confirmed 2026-09-29 when `test-architecture-implementer` proposed a mutmut baseline on
"docs/mechanics/03_economic_laws.md atomic conservation, mainly src/systems/". That run would have
mutated 2–3 line shims and reported a near-vacuous score indistinguishable from a well-tested
surface — the exact outcome its synthetic-target fallback existed to avoid, arriving through the
target choice instead of the tooling.

**How to apply:**
- Any measurement, mutation or coverage claim about conservation names `src/core/conservation.py`.
- Check line count before declaring a `src/systems/*.py` file a measurement target at all.
- `src/core/inventory.py` (265 lines) is the obvious co-target but is claimed by the open **P1**
  `TCK-20260914-ITEM-REGISTRY-DUAL-CLASS-DIVERGENT-FAILURE-SEMANTICS` (two `ItemRegistry` classes,
  divergent failure semantics). Exclude it until that closes.
- The `pressure-propagation-economy` epic threatens the *price/market* surface
  (`economy_systems/economy.py`, `src/economy/health_monitor.py`), **not** conservation.

  rather than answering only the question as asked.
