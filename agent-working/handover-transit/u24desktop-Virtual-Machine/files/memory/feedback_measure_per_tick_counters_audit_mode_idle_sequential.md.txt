A first before/after table I took (2026-10-03) was invalid: with `audit_mode` off, `kernel.py` `should_throttle` (~612-620) drops authoritative items whenever a tick exceeds `max_tick_budget_ms`, and loaded-machine runs of identical code gave different outcomes (e.g. 588 vs 319 opportunity attacks). A "3 -> 20 decision-path attacks" headline was a throttle artifact; the real figure was 3 -> 1.

**Why:** unthrottled measurement is the only way a before/after is attributable to the change. The planner's baseline (783 / 20 / 3 on frontier_living_world) reproduced exactly only once I did this.

**How to apply:** `PROD_SMALL.model_copy(update={"max_tick_budget_ms": 1e9})`, `flags audit_mode=True`, `LocalSequentialExecutor()`, one run at a time with nothing else on the CPU, sha256 of every entity's `to_canonical_dict()`, and a repeat of each arm. Compare your own before to your own after, never to someone else's instrument. If an arm is not reproducible even then, that is itself a finding (see `TCK-20261003-COMBAT-TACTICAL-PATH-NONDETERMINISM-SURVIVES-AUDIT-MODE`): do not call a determinism sweep green unless it set audit_mode. Related: [[project-slow-regression-determinism-root-cause]].
