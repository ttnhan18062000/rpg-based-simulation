**A piece of information must be defined in one document only. Avoid repeating it at all cost.**

Stated by the user 2026-09-16, after a whole arc spent measuring what duplication costs.

**Why:** document drift. Two hand-authored copies of the same fact diverge, and the divergence is
silent — a reader opening the stale one has no signal that it is stale. Measured in this repo:
2 stale atlas badges, **17% of wiring-map nodes** carrying the wrong state (4 of 24), a registry
seeding error, and a wrong claim in the very plan that argued for fixing duplication. Every layer
drifted, all authored carefully, by people actively checking.

**The distinction that makes it workable:** *defined once, rendered many times* is fine.
*Authored twice* is not.

- A generated view derived from a single source is a **rendering** — the definition still lives in
  one place. Fine.
- A second hand-maintained copy, even a faithful one, even in a different register for a different
  audience, is a **duplicate**. Not fine.

**How to apply:**

- Before writing a fact into a document, ask where it is already defined. If it exists, link or
  generate from it — do not restate it.
- Publishing an artifact that embeds numbers copied from a generated source creates a duplicate.
  Generate the artifact from the same source instead. (I did exactly this and had to undo it.)
- A "mirror this into that document too" rule is a duplication mandate. It is a sign the second
  document should be generated, not hand-synced — see
  [[feedback-sync-capabilities-with-atlas]], which exists only because generation did not.
- When consolidating sources, remember the cost: disagreement between duplicates was itself an
  accidental signal. Removing it means verification has to become deliberate.
