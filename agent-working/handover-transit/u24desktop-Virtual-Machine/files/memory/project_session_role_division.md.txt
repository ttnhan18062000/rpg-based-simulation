**Why:** two sessions actively writing code in the same shared working directory at the same time
compounds branch-thrashing (see [[feedback_worktree_by_default]]) and parity-ledger ID collisions
(confirmed live during PR #123's merge, and again 2026-09-09 when PR #148 and PR #149 both claimed
`INFRA-413`) — implementation has far more file-level collision surface than planning/ticket/review
work. It also keeps a clean reviewer/implementer split, which caught real defects repeatedly across the
KGMCP arc (PRs #147–#157) precisely because the reviewing session had not written the code.

**How to apply:**
- Do not implement anything — no `src/`, `frontend/src/`, `tools/`, schema, parity-ledger, workflow, or
  agent-config edits — unless the user explicitly lifts the scope for that task.
- Stay in: investigation, roadmap/epic scoping, ticket creation, staging artifacts
  (`investigation.md`/`plan.md`/`test_plan.md`), reviewing peer PRs, feature-atlas/capabilities-page
  maintenance, and checking shipped work against its commitments.
- **Stop at the Plan phase and hand off.** Complete Investigate + Plan, commit and push the branch with
  the ticket in `tickets/inprogress/` and its staging artifacts, then `SendMessage` the implementer with
  the branch name and what Review should scrutinize. Agent-infra work goes to `agent-working-implementer`.
- "Pick these next" or "proceed" from the user means drive the work forward, **not** a license to
  implement it — confirm the handoff point rather than assuming.
