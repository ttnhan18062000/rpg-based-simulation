When verifying a ticket that makes a previously opt-in or dormant code path **default-on**, check
that everything the path *emits* is already registered where it must be — not just that the flip
itself is correct.

**Why:** a dormant path ships "complete" and passes its own tests because nothing exercises it. Its
incompleteness surfaces later, as a CI failure on an unrelated PR belonging to whoever happens to
run next, where it is expensive to diagnose and looks like their bug. Confirmed 2026-09-23: PR #240
(verified by me) flipped shadow-reviewer collection default-on in `.claude/workflows/implement-ticket.js`,
which emits `architecture-reviewer-shadow` and `security-reviewer-shadow`; neither was in
`tools/agent-monitoring/vocabulary.py`. The path had produced 3 events ever, so nothing caught it.
It tripped the `vocabulary_drift` ratchet on `rpg-feature-planning`'s PR #241. `rpg-implementer`
diagnosed it, filed `TCK-20260923-SHADOW-REVIEWER-VOCABULARY-GAP`, established the register-don't-raise
precedent, and caught a second instance in
`tests/agent_orchestration/test_bootstrap_vocabulary_equality.py`.

**How to apply:** on any default-on flip, grep the enabled path for the literals it writes (agent
names, phase names, event kinds) and confirm each is registered in the corresponding registry.
`vocabulary.py`'s own precedent is **register the literal, never raise the ratchet ceiling**. The
narrow fix worth building is a static check over `.claude/workflows/*.js` asserting every
`agent: '<literal>'` / `writeSidecar(..., '<literal>')` is in `vocabulary.py` — not a general
"dormant path" gate, which is unsolvable and would violate
[[feedback_agent_tooling_checks_proportionate]]. Related: [[feedback_file_tickets_for_workflow_gaps]].
