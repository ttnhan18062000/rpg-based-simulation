When child tickets cite a plan's sections as their design source (e.g. "per plan §3.7"), the plan
must be committed and pushed **with** the tickets, even if it was deliberately kept untracked to
honour [[feedback_no_plan_only_prs]]. Otherwise the implementer reads a ticket pointing at a file it
cannot see, and reconstructs the design from the dispatch message — losing exactly the verified
detail that [[feedback_push_ticket_before_dispatching]] exists to preserve.

**Why:** the two rules look like they conflict but do not. "No plan-only PRs" forbids a PR whose
*only* content is a plan. A PR carrying tickets plus implementation plus the plan they cite is not
plan-only, so committing the plan there satisfies both rules. Confirmed 2026-09-24 scoping the
github-delivery-process epic, where the plan had been held untracked across a `/clear` on purpose
and six child tickets cited §3.5/§3.6/§3.7.

**How to apply:** before dispatching, grep the tickets for references to the plan. If any ticket
cites it, stage the plan in the same commit as the tickets. Keep a plan untracked only while no
committed artifact points at it.

**Same defect applies to a doc's cited *evidence*, not just plans, and `tmp/` makes it worse.**
Confirmed 2026-09-27 on `docs/plans/systemic_world_roadmap.md` (PR #249): the roadmap said it "stays
high-level and cites [its evidence] by pointer", pointing at `tmp/rpg-core-investigation-*.md` — and
`tmp/*` is gitignored at `.gitignore:226`, so every load-bearing claim resolved only on the authoring
session's machine. The same PR's six cited first-wave briefs in `tickets/todos/systemic-world-first-wave/`
were also local-only. The fix is **relocation, not `git add -f`**: move the artifacts to a tracked home
(`stored_artifacts/` is this repo's convention, and they need valid frontmatter), then update the
citations in the same commit so the pointers resolve. Verify against the pushed ref
(`git ls-tree -r <head> -- <path>`) or the PR's own file list — a peer reporting that a file exists is
reporting its local tree, not the remote.
