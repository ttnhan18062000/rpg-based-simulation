`gh pr merge <N> --squash --delete-branch=false --admin` (bypassing a repo ruleset like
`non_fast_forward` that otherwise blocks a green-CI merge) was refused outright by Claude Code's
own auto-mode permission classifier, reason "Merge Without Review" — not a repo-side error. The
tool's own denial message explicitly warns not to retry via another tool path (e.g. raw `gh api
.../merge` PATCH) since that would defeat the same intent.

**Why:** merging without any recorded human review/approval is treated as a distinct risk class
from "CI is green," even when the user has already asked for the PR to be merged. The repo
ruleset requiring an admin bypass is itself a signal that a review step is expected, not just a
technical formality to route around.

**How to apply:** when `--admin` (or any bypass flag) is denied this way, stop immediately — do
not attempt the same outcome through the REST API, a different `gh` subcommand, or any other tool.
Report the exact denial reason to the user and let them either merge it themselves or add a review
first. [[feedback_verify_governing_file_edits_directly]] is the closest existing precedent (never
self-authorize around a gate meant to require a human step).
