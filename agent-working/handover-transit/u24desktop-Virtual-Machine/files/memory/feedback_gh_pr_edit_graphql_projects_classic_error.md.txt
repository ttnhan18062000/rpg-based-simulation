`gh pr edit <N> --title "..."` can fail outright with:
`GraphQL: Projects (classic) is being deprecated in favor of the new Projects experience... (repository.pullRequest.projectCards)`

This error is unrelated to the field actually being edited — `gh pr edit` apparently fetches
project-card metadata as part of its response even when not requested, and errors out on repos
where that legacy API path is now blocked. The edit does not go through when this happens (verify
with `gh pr view <N> --json title -q .title` — it silently stays unchanged, no partial write).

**Workaround**: use the REST API directly instead of `gh pr edit`:
`gh api repos/<owner>/<repo>/pulls/<N> --method PATCH -f title="..."` (or `-f body="..."` for the
body). This bypasses whatever `gh pr edit` internally fetches and works reliably.

**How to apply**: whenever `gh pr edit` fails with a GraphQL error mentioning "Projects (classic)"
or `projectCards`, don't retry `gh pr edit` — switch to `gh api ... --method PATCH` for that same
field, then verify with `gh pr view --json <field>`.

**Why**: confirmed live on `rpg-based-simulation` PR #257 (2026-09-29) when fixing a misleading
auto-rendered PR title — `gh pr edit 257 --title "..."` failed with this exact error, `gh api
repos/ttnhan18062000/rpg-based-simulation/pulls/257 --method PATCH -f title="..."` succeeded
immediately with the same title string.
