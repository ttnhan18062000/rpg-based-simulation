On 2026-10-03 the owner said "you can continue on a big batch, not create small PR", after a run of one-ticket hotfix PRs (#293, #295).

**Why:** many small PRs each cost a CI cycle, a render/check, a push go and a merge; the owner prefers fewer, larger batches. It matches [[feedback_finalize_feature_completely]] and [[feedback_push_to_open_pr_not_new_stacked_pr]].

**How to apply:** when a fix is found while a PR on the same track is open (for example the native `implement-ticket` path), ask the implementer to fold it into that open PR (check it has not merged first, re-render the body, run `pr_render --check`) instead of a second PR. Bundle related hotfixes into one branch. Never fold a different domain's work in. Pushes and merges still need the owner's go in the implementer's own terminal.
