When planning process or architecture (e.g. the test-architecture epic, 2026-09-28), base every direction on popular, established industry approaches and cite them (papers, Google Testing Blog, Fowler, tool docs), and give each plan a References section. Don't build anything "on your own without any reference or citation."

**Why:** The user said, mid-planning: "make sure you look at the popular internet approach, don't build anything on your own without any reference or citation." It extends [[feedback-prefer-popular-skills-over-custom]] from skills to plans and process design.

**How to apply:** WebSearch for the canonical sources before proposing options. Tag each option or direction with [R#] cites. Check whether an already-installed community skill covers the need (e.g. the obra/superpowers `test-driven-development` skill ships `testing-anti-patterns.md`) before proposing anything new. Present decisions as options plus a recommendation, per [[feedback-options-and-recommendation-on-concerns]].
