## Notes

**Integrity check:** `make agent-monitoring-validate` reports ~55 "DONE but no working_log entry"
warnings, but every one predates this window (2026-06-10 through 2026-07-01 tickets) — a legacy
gap from before the current record-keeping convention, not something this week's 29 runs
introduced. Not investigated further per established scope (legacy-format gaps are expected, not
regressions to chase).

### 1. What failed most?

`done-checker` (Verify gate) is the single worst-performing agent this week: **8 failed / 23
calls (35%)**. `architecture-reviewer` is second: **9 failed / 42 calls (21%)** across its two
call sites (pre-Implement Review + post-Implement Architecture-Verify). Notably, the Gate Failure
Breakdown table shows only 1 final `NEEDS_CHANGES` and 0 final `DOD_BLOCKED` outcomes — meaning
almost all of these 17 combined failures were absorbed by same-session retries (fix → re-run the
phase) rather than terminating the run. The 8 `dod_condition_failed` reason-code events (Reason
Codes table) line up with `done-checker`'s failure count exactly, confirming Verify is where
iteration cost concentrates, even though it rarely blocks a ticket outright.

### 2. What was slow?

Spend concentrates in three phases: **Implement** (42553.5 total / avg 3039.5 — expected, it
writes the code), **Scope** (33649.8 total / avg 2403.6), and **Investigate** (32325.1 total / avg
2308.9). Scope's cost is higher than its role suggests — worth checking whether `ticket-scoper` is
doing Investigate-sized work (deep codebase reads) rather than staying at triage depth.
Two runs required manual `STOPPED_BY_USER` intervention at **839 min** and **541 min**
(`FOLDER-tickets-todos-simq-scoring-improvement`, `TCK-20260714-SIMQ-WEIGHTS-PILLAR-COLLISION`) —
both far outside the normal 1–3 hour range every other run falls into, suggesting an occasional
runaway-session failure mode worth a follow-up look (what made those two get stuck rather than
gate-fail cleanly?).

### 3. What to change?

- **Fix the Plan-phase "unresolved question" gate** (`implement-ticket.js`, Phase 3): it checks
  `planText.toLowerCase().includes('unresolved question')` against the planner's free-text return
  summary. Hit this firsthand this week on `TCK-20260716-SIMQ-URBAN-POLITICAL-FULL-PILLAR-SWEEP`
  — the planner wrote "**No** unresolved questions" (both open items resolved in a Decision
  section), which still matches the substring check and would have falsely triggered
  `NEEDS_HUMAN_INPUT`. Caught it by reading `plan.md` directly (no genuine `## Unresolved
  Questions` heading present) and proceeding past the false positive. Fix: check `plan.md` itself
  for a real `## Unresolved Questions` heading rather than substring-matching the agent's prose
  summary.
- **Add write protection to `agent-monitoring/tools.jsonl`**: found and repaired a corrupted line
  this week caused by two concurrent sessions' tool-tracking writes interleaving without a
  newline between them (mid-write race, not append-atomic). Since this file is the raw input to
  this exact retro process, a silent corruption here degrades every future week's numbers, not
  just the run that caused it. Worth an `flock`/atomic-append fix if concurrent sessions are a
  regular occurrence (Scope phase increasingly overlaps with other in-progress work, per this
  week's own experience working alongside a second live session).
- **Audit the 8 `dod_condition_failed` events for a common root cause** — if they cluster on one
  or two specific DoD conditions (e.g. staging-artifact completeness, frontmatter validity), that
  points to a fixable upstream gap (Investigate/Plan should produce it correctly the first time)
  rather than 8 independent one-off misses.

### 4. What worked?

- **Hotfix tier: 4/4 (100%) DONE rate** — the fast-path routing is functioning exactly as
  designed; no gate friction for minimal targeted fixes.
- **Once a ticket clears Review, downstream execution is highly reliable**: `implementer` 18/18
  ok, `finalizer` 15/15 ok, `test-scoper` 17/17 ok — 100% across all three. The failure modes this
  week are concentrated at the two judgment gates (Review/Architecture-Verify and Verify), not in
  code-writing or test-running.
- **`simulation-quality`-tagged work is the dominant workload this week** (22 of 29 runs, 81% DONE
  rate) and is performing above the overall 79% average — the SIMQ ticket chain's established
  patterns (evidence-derived tolerance overrides, append-only parity-ledger discipline) are
  holding up well under repeated reuse.
