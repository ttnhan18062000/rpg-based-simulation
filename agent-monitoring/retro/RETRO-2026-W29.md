## Notes

### 1. What failed most? — `done-checker` BLOCKED on uncleaned `data/runs/`, recurring across weeks

Within this window `done-checker` is 8 ok / 5 failed (62% pass rate), the weakest gate in the pipeline. Pulling the last 7 days of raw events shows this isn't a one-off: `data/runs/` (and occasionally `reports/release_proof/`) being uncleaned at Verify time is the single most repeated BLOCKED reason across *both* this week and last (TCK-20260706-SIMQ-CORPUS-RESOURCE-REG — 44 dirs, TCK-20260707-CORPUS-POPULATION-STABIL — 37 dirs, TCK-20260707-SIMQ-LONGRUN-HOTPILLAR — 139 dirs, TCK-20260708-DUNGEON-URBAN-POPULATION, TCK-20260713-SIMQ-COGNITION-PIPELINE-WIRE, TCK-20260713-SIMQ-ECONOMY-INTENT-GENERATION-GAP — 36 dirs contradicting the ticket's own cleanup claim).

Root cause: per CLAUDE.md's tier pipelines, **Verify runs before Finalize**, but the `rm -rf data/runs/* reports/release_proof/*` cleanup step is documented under Finalize's "After Work" checklist. So `done-checker` is structurally gating on a condition that the pipeline hasn't performed yet — every run either passes by luck (agent cleaned up early anyway) or fails and burns a retry round. The second-most-common BLOCKED reason (ticket sections — Completion Summary/Files Changed/Test Summary left empty) has the same shape: a Finalize-owned task being checked at Verify.

**Action:** move `data/runs/`/`reports/release_proof/` cleanup (and drafting the Completion Summary/Files Changed/Test Summary sections) to happen at the end of Implement/Test, before Verify runs — not solely as a Finalize step. This should cut done-checker's BLOCKED rate substantially without changing what's actually required.

### 3. What to change? — planner keeps omitting required companion-doc updates on SIMQ tickets

Three separate `architecture-reviewer` NEEDS_CHANGES this week called out the plan missing a required doc update: `quality_scoring_contract.md §11.3` (SIMQ-RAWSCORE-PERSIST), `authoritative_pipeline.md` phase table + `feature_flags.md` 10-flags table (SIMQ-COGNITION-PIPELINE-WIRE, twice — the second review still found renumbering/count gaps after the first fix). This is a planner-prompt gap specific to tickets touching the Mechanics Bible/engine-contract surface: it's not cross-checking the full set of documents that reference the changed mechanism before finalizing plan.md.

**Action:** add an explicit planner checklist step for SIMQ/mechanics-adjacent tickets: grep every doc that references the phase/flag/contract being changed (not just the primary doc) before submitting plan.md for architecture review, to avoid the multi-round NEEDS_CHANGES cycle seen on SIMQ-COGNITION-PIPELINE-WIRE.
