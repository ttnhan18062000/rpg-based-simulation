## Notes

**1. What failed most?** `done-checker` has the highest failure count of any agent (25/68 calls,
37%), and `dod_condition_failed` is by far the dominant reason code (25 of 27 total gate-failure
reason codes this week). Two runs this session (`TCK-20260710-SIMQ-ANCHOR-RELIABILITY-VERIFY`,
`TCK-20260710-TOWN-COUNCIL-HAZARD-DA`) both hit `DOD_BLOCKED` on their *first* Verify attempt —
once for a missing frontmatter block on a new staging artifact, once for an invalid
`artifact_type` enum value on another, and once for an empty `## Completion Summary` section left
blank by the implementer. All three were one-line fixes caught late (at Verify) rather than early
(at Implement/Finalize), costing a full done-checker round-trip each time.

**2. What was slow?** `Implement` (593.2 avg) and `Finalize` (486.9 avg) are the two most expensive
phases by spend-proxy, and several `Slow Runs` entries (`TCK-20260710-CURRENT-RUN-SIDECAR-BASH` at
475 min, `EPIC-TCK-20260710-AGENT-BOOKKEEPING-DETERMINISM-EPIC` at 548 min) plausibly reflect the
same pattern directly observed this session: the `implementer` agent launching a long-running
background Bash command (a pytest run, a multi-trial calibration sweep) and then ending its own
turn before the command finished, believing — incorrectly — that it would be auto-resumed the way
the orchestrator is. This happened three separate times in one ticket
(`TCK-20260710-SIMQ-ANCHOR-RELIABILITY-VERIFY` alone), each requiring the orchestrator to manually
detect the still-running process, wait for it via `Monitor`, and re-send the implementer a status
update before it could continue. Not visible as a "failure" in this report's gate metrics, but a
real wall-clock cost.

**3. What to change?**
- Add an explicit reminder in `implement-ticket.js`'s staging-artifact-creation instructions (both
  Investigate and Implement phases, anywhere a new `staging_artifacts/{ticket_id}/*.md` file is
  authored) to always include a valid frontmatter block matching the existing sibling files'
  format, with `artifact_type` drawn from the same enum `done_checker_static.py` enforces — this
  would catch both of this week's frontmatter-class `DOD_BLOCKED` failures before Verify ever runs.
- Add explicit guidance to the `implementer` agent (and any other subagent role) that it must not
  end its turn while a `run_in_background` command it started is still running — either run
  in the foreground, or poll for the command's own completion within the same turn. This is
  already being said ad hoc in per-call prompts by the orchestrator this session; it belongs in
  the agent's own standing instructions instead so every future run gets it by default.

**4. What worked well?** The static pre-check backstops (`done_checker_static.py`,
`architecture_reviewer_static.py`) continue to catch real issues deterministically rather than
relying on LLM judgment alone — both this week's `DOD_BLOCKED` runs were correctly diagnosed via
the static script's exact JSON output, and the retry after a one-line fix passed cleanly both
times. The Parity phase's skip-eligibility logic (no `src/` changes + `behavior_changed=false` + no
P0 intersection) correctly avoided unnecessary `parity-updater` agent calls on two doc-only tickets
this week. Sequential epic execution via `SEQUENCE.md` ordering worked correctly across two
separate epic folders (`simq-roadmap-phase0-reliability-foundation`,
`simq-roadmap-phase1-process-hardening`), including correctly deferring a folder-to-done move when
a sibling ticket in the same folder was still outstanding.
