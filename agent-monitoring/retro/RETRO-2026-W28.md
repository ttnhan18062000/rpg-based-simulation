## Notes

**1. What failed most?** `done-checker` (Verify phase): **22 of 61 calls (36%) failed on first
attempt**, every one tagged `reason_code: dod_condition_failed` — this single agent accounts for
more failures than every other agent combined, and the `dod_condition_failed` reason count (22)
dwarfs the run-level `DOD_BLOCKED` gate count (2), meaning most of these failures were caught and
*fixed within the same run* rather than terminating it. This isn't hypothetical: 2 of the 3 tickets
closed in this session alone (`TCK-20260711-EPIC-SCOPE-ORPHAN-FIX`, `TCK-20260711-EPIC-STALENESS-DEDUPE-CHECK`)
failed their first Verify pass for the *identical* reason — a behavior-changing Implement phase that
didn't update the `docs/` file describing the changed behavior, caught only at Verify, fixed, then
Verify re-ran clean.

**2. What was slow?** `Investigate` is the most expensive phase by a wide margin (avg cost-proxy
483.5 vs. the next-highest, `Verify`, at 147.1) — consistent with its mandate to do a full context
scan (`search_docs`, `graphify`, affected code/docs/parity-ledger/stored_artifacts) before any
planning starts. Not obviously avoidable: this session's own deep investigations found real bugs
(`implement-epic.js`'s silent `Discover`/`Report` event gap) precisely because of that depth — cutting
Investigate scope to save cost would likely cost more in missed findings than it saves. The 3
longest wall-clock runs (548/475/396 min) belong to a different concurrent session and don't reflect
pure compute time; wall-clock duration isn't a reliable slowness signal without an active-compute-time
metric to separate it from idle/interleaved gaps.

**3. What to change?** One concrete action: add a proactive doc-staleness check that runs before or
during Verify, rather than relying entirely on `done-checker`'s own per-run judgment call each time —
e.g., a static check (mirroring `workflow_meta_conformance.py`'s shape) that flags "a `src/` or
`.claude/workflows/*.js` file changed with `behavior_changed=true`, but no `docs/` file was touched in
the same diff" during Parity or pre-Verify. The 22-count `dod_condition_failed` reason code across
this single week — not a one-off — gives this real weight as a recurring failure class worth closing
with a gate, following the same near-horizon-mitigation pattern this session already used for
`tools/gate_checks/workflow_meta_conformance.py` and `tools/agent-monitoring/epic_scope_orphan_check.py`.

**4. What worked?** Confirmed good patterns, worth keeping: `parity-updater`'s skip-eligibility check
(19 of 39 calls skipped) is correctly avoiding unnecessary agent calls when there's no `src/` change
and no behavior change. `architecture-reviewer`'s Architecture-Verify skip logic (20 of 89 calls
skipped, hotfix tier) is similarly working as designed. And despite its high first-attempt failure
rate, `done-checker`'s retry-after-fix loop is doing its actual job: no ticket closed this week shows
evidence of a known-but-unstated gap shipping to `done` — every caught DoD failure this week was
fixed before Finalize, not silently bypassed. The gate is expensive but not broken.
