## Notes

This week is dominated by the `m1-quick-wins` batch: 22/22 tickets landed (plus 2 pre-work
hotfixes and 5 tooling/process follow-up tickets filed). 91% DONE rate, 6 gate hits total —
consistent with a batch this size touching combat/social/cognition/world code with real
architectural review at every standard-tier ticket.

### 1. What failed most?

- **`architecture-reviewer`**: 13/88 calls failed (highest raw fail count of any agent). All
  observed instances this week were genuine, substantive findings (e.g.
  `TCK-20260824-TOWN-CENTER-POINTER-FIX`'s Review round 1 caught a real missed P0 parity entry,
  `SUB-014`, describing the exact mechanism the plan was about to change) — none were
  false-positive noise. This is architecture review doing its job, not a problem to fix.
- **`done-checker`**: 16/53 calls failed. Two distinct causes, one real and repeated, one a
  confirmed tooling bug:
  - **Repeated real cause**: the ticket's own `## Files Changed` section omitting a doc the
    Document-Update phase had legitimately touched, catching this at Verify instead of earlier.
    Hit on at least 4 separate M1 tickets this week (`WOUND-THRESHOLD-DECISION`,
    `TACTICAL-WOUND-SCAR-WIRING`, `REPUTATION-WITNESSED-EVENT-WIRING`,
    `AFFECTION-CONTRACT-GATE`). Always fixed by completing the ticket's own record (real
    substance fix), never routed around — but the same class recurring 4+ times in one batch is a
    real process gap worth closing at the source (see "What to change" below).
  - **Confirmed tooling bug**: `check_docs_to_update_coverage`'s static checker is a pure
    path-presence regex with no content awareness — it cannot recognize a conditional
    `investigation.md` bullet resolved as not-applicable, regardless of what prose follows the
    path. Hit on `AFFECTION-CONTRACT-GATE`, independently verified twice (once directly, once by a
    separately-dispatched `done-checker` agent's own fresh re-check) before an explicit,
    documented human override. Filed as `TCK-20260829-DOC-COVERAGE-CONDITIONAL-BULLET-BLIND-DOD-BLOCKED`,
    not yet fixed as of this report.
- **`test-scoper`**: 5/41 calls failed, all the same structural cause — the test-scope-coverage
  backstop catching a scoped pytest command that cherry-picked test files instead of including
  the bare test directory a shared/core `src/` file's change requires. Hit repeatedly across the
  batch (`WIRE-ORPHANED-MECHANISMS`, `OCCUPATION-CHANGE-TRIGGER`, `RELATIONSHIP-ROLE-FIELD`,
  others). Always caught and fixed correctly (re-scoped, re-ran), never silently narrowed.
- A second known checker false-positive, `plan_gate_static.py`'s heading-presence-only
  Unresolved-Questions check (filed earlier as `TCK-20260827-PLAN-GATE-HEADING-CONTENT-BLIND-FALSEPOS`),
  also fired multiple times this week but was correctly recognized and bypassed per its own
  documented exception each time — contributing to the `NEEDS_HUMAN_INPUT` reason-code count
  without ever being a real blocker.

### 2. What was slow?

`idle` minutes relative to `active` minutes (e.g. `RELATIONSHIP-ROLE-FIELD`: 31 min active / 728

readers of future retros should trust `active` minutes as the real work-time signal for this

### 3. What to change?

1. **File a tooling ticket for the recurring Files-Changed-omission → done-checker BLOCKED
   pattern** (distinct from the two already-filed gate-checker bugs): since Document-Update runs
   before Verify and its own `docs_updated` list is already known at that point, `implement-ticket.js`
   could cross-check the ticket's own `## Files Changed` section against Document-Update's real
   output *at Document-Update time* (a warning/auto-fill), rather than only catching the gap much
   later at Verify. This would have prevented 4+ of this week's `done-checker` failures at the
   source.
2. **Prioritize actually fixing `TCK-20260827-PLAN-GATE-HEADING-CONTENT-BLIND-FALSEPOS` and
   `TCK-20260829-DOC-COVERAGE-CONDITIONAL-BULLET-BLIND-DOD-BLOCKED`** — both fired multiple times
   this single week and both already have a clear, scoped fix designed in their own ticket text;
   they're cheap, high-value fixes given the repeat rate.
3. **Reinforce in `test-scoper`/`implementer` prompt guidance**: when a changed `src/` file is
   shared/core (not a leaf module), the scoped pytest command must include the bare containing
   test directory, not cherry-picked files within it — this is already a known pattern (see prior
   session memory), but recurred 5 times in this one batch, suggesting the guidance isn't
   consistently reaching sub-agents. Consider adding it as a standing line in the `test-scoper`
   agent definition itself rather than relying on each dispatch prompt to restate it.

### 4. What worked?

- **Gate Integrity discipline held with zero exceptions across 22 tickets**: every real
  `NEEDS_CHANGES`/`TESTS_FAILED`/`DOD_BLOCKED` finding this week was resolved by fixing genuine
  substance or, for the two confirmed checker bugs, via an explicit, independently-double-verified
  human override — never a silent edit to an artifact to dodge a check. Both confirmed
  false-positive classes were separately ticketed rather than patched inline.
- **The parity-ledger corruption-risk protocol** (run `git diff --stat`, and for large diffs
  independently verify entry-count + per-entry content-equality against `HEAD` rather than trusting
  line-count alone) worked cleanly across ~10+ parity-touching tickets this batch — caught and
  fixed one real ad-hoc-rewrite corruption case, correctly identified every sanctioned
  full-shard-rewrite as safe, zero false alarms in either direction.
- **Fresh-agent recovery from session/process interruptions** (reading real on-disk diffs against
  a ticket's own `plan.md` to determine true pipeline state, rather than restarting work) reliably
  preserved real, substantial work across at least 5 separate interruption events this batch — no
  work was lost or duplicated.
- **Filing tooling-gap tickets instead of patching gate checkers inline** (5 process/tooling
  tickets filed this batch, distinct from the 22 gameplay tickets) kept gate logic itself
  auditable and traceable rather than accumulating undocumented ad-hoc exceptions.
