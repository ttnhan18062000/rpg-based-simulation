## Notes

**This is the first retro report ever generated from real data.** The tool was scaffolded 2026-06-12; `agent-monitoring/retro/RETRO-ALL.md` sat as a zero-data smoke-test artifact for ~4 weeks and 310 completed `implement-ticket` runs before this report. See "What to change" below for the process fix that closes this gap going forward (`TCK-20260704-RETRO-LOOP-ENFORCEMENT`, already shipped).

1. **What failed most?** `architecture-reviewer` — 9 failed / 48 calls (19%) this week, the highest failure rate of any agent. This is a *good* signal, not a bad one: spot-checking several of this week's failures (including two from this session's own `implement-epic` run) shows the reviewer catching real, substantive issues — a plan's new-doc frontmatter deviating from established convention, a parity-ledger entry that would go stale, a crash risk on legacy data — not noise or false positives. `done-checker` failed 2/39 (5%), both legitimate `DOD_BLOCKED` catches. Read together, these are exactly the pipeline gates doing their job; the metric to watch going forward isn't "make this number zero," it's whether the failure *reasons* stay substantive.

2. **What was slow?** Unable to assess — `Avg duration: 0 min` and `Slow Runs: none` both look structurally suspicious rather than genuinely fast, most likely because a large fraction of this week's runs are missing `end_ts` (see the historical validation finding below) and get excluded or zeroed out of the duration calculation rather than counted as slow/incomplete. This metric isn't trustworthy yet.

3. **What to change?**
   - **Empty summaries: 24 this week (matches the ~13% all-time rate found before this retro existed).** Prioritize fixing the agent prompts most responsible — cross-referencing the Agent Status table, `architecture-reviewer`, `investigator`, `planner`, and `test-scoper` all show 5 "skipped" phase-events with likely-empty summaries (hotfix-tier skips correctly render as `skipped`, but worth confirming the empty-summary count isn't double-counting those rather than genuine agent-output gaps).
   - **Broader, more urgent finding from `make agent-monitoring-validate` (all-time, not just this week): 180 total warnings, including 5 hard errors (`ERROR: Run with no events`) and 21 runs with `no end_ts (CRASHED?)`, plus 38+ `DONE` runs in `working_log.csv`-mismatch state** — concentrated in June 19–July 1 (E13C/E41C/E42–43/E53/E62–63 phase batches, SIMQ EMIT/WIRE/UPLIFT batches, and the June 23 FIX-* batch). This predates and is unrelated to this week's work, but it's real, unaddressed data-integrity debt that undermines trust in any aggregate stat pulled from `runs.jsonl` (including this report's own "Avg duration" and "Slow Runs" fields — see point 2). Worth a dedicated follow-up ticket to investigate root cause (a crash-handling gap? an incomplete `writeMonitoring` call somewhere?) rather than silently living with it.

4. **What worked?** 96% overall DONE rate; hotfix tier at literal 100% DONE (18/18) confirms the fast-path tier routing is functioning as designed, not just fast in theory. `ticket-scoper` is at 44/44 `ok` with zero failures — ticket scoping itself is a solid, low-risk phase.
