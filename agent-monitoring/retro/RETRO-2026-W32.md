## Notes

- **Index staleness (fixed for this report, not fixed at the tooling level):** the derived SQLite
  index `generate_retro.py` reads from only auto-rebuilds when the DB file is *missing*, not when
  it's stale. Before a manual `make agent-monitoring-index` rebuild, this report showed only 7
  runs/34 events for the week — silently missing every run/event written since the index was last
  built (20+ runs, including all of the doc-updater work below). No warning is surfaced when this
  happens. Worth a follow-up ticket to either force-rebuild on every `generate_retro.py` invocation
  or emit a loud staleness warning when the index's newest row predates the JSONL files' newest row.
- **Document-Update / doc-updater confirmed live:** 1 call, `ok` status, in both the Agent and
  Phase Status Distribution tables — the first real execution of the new phase since
  TCK-20260803-DOC-UPDATER-EPIC shipped it (TCK-20260804-DOC-UPDATER-ROLE-FILE).
- **Spend Proxy under-reports the epic close + role-file hotfix (9 events, both zeroed):** those
  events were hand-recorded with an incomplete `.claude/current_run` sidecar (missing `run_id`/
  `seq`), so `record_events.py`'s authoritative `tools.jsonl`-keyed lookup found nothing and
  correctly zeroed `tool_call_count`/`cost_proxy_score` rather than trusting the caller-supplied
  values — by design, not a bug, but means this week's Spend Proxy totals for `Document-Update`,
  and the `Finalize`/`Scope` rows touching those two run_ids, undercount real cost. The 3 earlier
  child tickets (CORE-WIRING/VOCAB-REGISTRATION/DASHBOARD-PALETTE) used the correct full sidecar
  shape and show real, non-zero figures.
- High DOD_BLOCKED rate this week (6/27, 22%) — largely self-caught documentation-accuracy issues
  (unchecked AC boxes despite true criteria, malformed "Docs Requiring Update" sections) across the
  doc-updater tickets and DOCS-STRUCTURE-AUDIT, all fixed as content corrections before Verify
  passed, not routed around.
