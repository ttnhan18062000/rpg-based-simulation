   written this session

Every `tools.jsonl` row logged this session (166 rows, `TCK-20260807-*`) has `run_id: null,
seq: null, phase: null, agent: null`. Confirmed via `.claude/current_run` reading `{}` (empty)

invisible to this report (they can't be attributed to any run), and this session's own
search-before-grep / parity-write-safety compliance cannot be measured by the automated audit —
not because compliance was bad, but because the linkage key is missing. **This is not unique to
this session**: 41,179 of 89,078 total `tools.jsonl` rows (46%) have `run_id: null`
corpus-wide — a long-standing, recurring gap in the hand-orchestration pattern, not a new
regression. **Action:** when hand-orchestrating `implement-ticket.js`/`simq-audit.js`/etc., write
`.claude/current_run` (`{"run_id":..., "seq":..., "phase":..., "agent":...}`) before each
significant tool call, per the existing (but evidently not consistently followed) convention —
this was flagged once before as a lesson-learned and clearly needs to be a harder habit, possibly
worth a `PreToolUse` hook nudge similar to the existing retro-cadence nudge.
