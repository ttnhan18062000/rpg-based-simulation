## Notes

**Process gap found and fixed while generating this report**: `agent-monitoring-index/monitoring.db`
was stale (last built 2026-08-10T14:15+07, before the first ticket of this session's 5-ticket
batch even closed). `generate_retro.py` reads from this SQLite index, not live JSONL, and only
rebuilds it on-demand if the file is *missing* — a stale-but-present index degrades silently. The
first retro run this session under-reported by 61% (7 runs / 41 events) versus the corrected number
after a manual rebuild (18 runs / 123 events) — several DONE tickets, most gate failures, and every
`architecture_violation`/`documentation_accuracy` reason code were invisible in the first pass.
Rebuilt directly (`build_index.build(...)`) before trusting these numbers. **Action**: either make
`generate_retro.py` check the index's mtime against `runs.jsonl`/`events.jsonl` and auto-rebuild on
staleness (not just on absence), or have `record_run.py`/`record_events.py` themselves invalidate/
touch the index on every write. Filing as its own hotfix ticket rather than patching ad hoc here.

1. **What failed most?** `Review` (architecture-reviewer, pre-Implement plan review): 12 calls,
   only 7 `ok` (58%), 5 `failed`. Every multi-step ticket in tonight's cognition/strategy batch hit
   at least one real `NEEDS_CHANGES` round — a stale doc-ownership citation that didn't exist, an
   overstated "detour always bypasses" claim contradicted by the real code, a duplicate-scope
   collision with a sibling ticket, an unaddressed edge-case in a normalization constant, a wrong
   function-signature citation. All 5 were genuine, evidence-cited findings (verified independently
   against real source in every case), not false positives — this reads as the gate doing its job on
   architecturally dense work, not a broken gate. `Verify` (done-checker) also had 3/17 failures, all
   `dod_condition_failed` — 2 were "disclosed gap needs a real ticket ID, not prose" (the established
   session pattern), 1 was an incomplete Files Changed section + a copy-pasted `phase:` frontmatter
   field where `artifact_type:` was required.

2. **What was slow?** `FOLDER-cognition-adventure-eligibility` (the 4-ticket batch, 416 min = 6.9h)
   and `TCK-20260810-PROJECT-SWITCH-BYPASS-GENERALIZATION` (196 min) are the two duration outliers
   (8.0x and 3.8x their tier median). Both are directly explained by Review-phase iteration — C2 in
   particular needed a 2nd architecture-review pass mid-Plan before Implement could even start.
   `Investigate` is the single most expensive phase by spend-proxy (3148.4 total, avg 314.8/call,
   nearly 4x the next-highest phase) — several Investigate agents this session ran real live
   simulation traces (1365-call `evaluate_project_switch()` monkeypatch trace, 32+ scenario seed
   runs) rather than reading code alone. That's real, load-bearing empirical work, not waste — the
   Plan phase's own numeric decisions (seed count, population size, recalibrated threshold) were
   directly grounded in it and held up under 2 independent re-derivations later in the pipeline.

3. **What to change?** (a) Fix the index-staleness gap above — highest-value, low-risk. (b) The
   search-before-grep compliance rate reads low (66.7%, 6/9) — likely a measurement-window artifact
   rather than a real hard-rule violation: this session's own hand-orchestration pattern runs the
   Context Scan (`search_docs`/`graphify query`) *before* writing the Investigate-phase sidecar, so
   those calls land in `tools.jsonl` tagged to whichever phase's sidecar was active at that moment,
   not the Investigate phase itself, even though the search genuinely happened first in wall-clock
   time. Worth a follow-up ticket to either reorder sidecar-write-before-scan in the skill docs, or
   teach the compliance metric to look one sidecar-window back. Not fixed here — flagging only, since
   confirming which explanation is correct needs its own investigation.

4. **What worked?** The Review→fix→re-Review loop this session consistently caught real defects
   before they shipped and none were routed around — every `NEEDS_CHANGES` got a direct, evidence-
   backed correction and a 2nd pass that re-verified against real source rather than re-trusting the
   fix. The pattern of independently re-deriving claimed empirical results (Architecture-Verify
   re-running the target test AND re-calling the landed helper function directly, rather than
   trusting Implement's self-report) caught nothing wrong in that case but is worth keeping as
   standing practice — cheap insurance against a class of error (self-report drift) other checks
   don't cover. Filing genuine follow-up tickets for disclosed-but-out-of-scope gaps (2 real ones
   this session: `TCK-20260811-INTERRUPTION-BYPASS-RETENTION-MARGIN-SCALE-BUG`,
   `TCK-20260810-COGNITION-STRATEGY-SKILL-BYPASS-SYNC`) rather than leaving them as prose continues
   to work well and should stay the default.
