# Implementation Plan - E5 Closure Hardening

I will implement the remaining P0 requirements from the Phase E5 review to achieve architectural closure and deterministic proof validation.

## Proposed Changes

### 1. Conflict Resolution (P0-2)
Hardening the resource resolver to prevent multiple entities from consuming the same single-use source in the same tick.
- **`src/core/conservation.py`**: Update `resolve` to check `reservations` for `GROUND_ITEM`, `CORPSE`, and `SHOP_BUY`.
- **`tests/engine/test_resource_conflicts.py`**: [NEW] Test cases where two actors attempt to loot the same corpse or pick up the same item simultaneously.

### 2. Transaction Grouping (P0-3)
Ensuring that intents sharing a `group_id` are always processed atomically, regardless of their position in the intent list.
- **`src/engine/pipeline.py`**: Verify/Refine the `OrderedDict` grouping logic to ensure it covers all non-contiguous cases and correctly rolls back all side effects (Inventory, Quest, Identity, etc.).
- **`tests/engine/test_transaction_grouping.py`**: [NEW] Test for non-contiguous intent groups and multi-component group rollbacks.

### 3. Protocol Validator (P0-5)
Establishing a machine-readable truth for the logic checklist.
- **`scripts/protocol_validator.py`**: [NEW] A validation script that checks the `logic_checklist_exhaustive_v2.md` for valid source and test paths.
- **`logic_checklist_exhaustive_v2.md`**: Update markers to follow a standard verifiable pattern: `[DONE] source:path/to/file test:path/to/test`.

### 4. Certification Gate (P0-1)
Closing the gap on fabricated proof.
- **`tests/certification/test_final_gate.py`**: Remove the code that fakes a passing bundle. Instead, the test will validate artifacts generated by the actual test suite in `reports/release_proof/`.
