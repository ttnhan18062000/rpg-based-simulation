# Investigation Notes: Cognition Pipeline Robustness & Safety

## Overview of the Implementation

Our structural audit of the Phase 10 implementation shows it completely satisfies the architectural constraints:
1. **Decoupled hook in Kernel**: `Kernel.advance()` calls `_cognition_recorder.record_tick` after all other phases are executed and committed. This guarantees that strategic graph capturing is strictly read-only and does not mutate active state.
2. **Deterministic graph hashes**: Graph hashes are generated by sorting keys and hashing the resulting JSON representation. This maintains exact replay determinism and ensures simulation runs can be reproduced perfectly byte-for-byte.
3. **Capture throttling**: Throttling uses a configurable `CognitionCapturePolicy` (OFF, LIGHT, DEBUG, LONG_RUN) that records only on specific triggers (objective changes, anomalies, overload changes) instead of every tick. This avoids disk bloat and performance degradation.
4. **Security boundary**: Standard input sanitization checks for path traversal characters (`/`, `..`) are applied through `sanitize_id` using an alphanumeric check (`^[a-zA-Z0-9_\-]+$`).

## Verification Metrics
- **Deterministic State hash integrity**: State hashes remain 100% identical between runs when observability is enabled or disabled.
- **Memory RSS footprint**: Incremental garbage collection and cache boundaries are verified. Snapshots and diffs use compact representations and truncations.
