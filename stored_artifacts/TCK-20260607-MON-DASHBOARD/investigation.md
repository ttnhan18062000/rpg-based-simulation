# Investigation — TCK-20260607-MON-DASHBOARD

## Summary

Add `agent-monitoring/retro/` as a fifth Docusaurus content-docs plugin instance
so weekly retro Markdown files appear under `/agent-monitoring/` in the docs site.

## What Exists

- `website/docusaurus.config.js`: 4 plugin instances (tickets, artifacts) + classic preset (docs)
  + @easyops-cn/docusaurus-search-local. No agent-monitoring plugin yet.
- `agent-monitoring/retro/`: `index.md` + `RETRO-ALL.md` (no per-week files yet)
- `agent-monitoring/retro/index.md`: table with link to RETRO-ALL.md — already serves as landing page
- Existing sidebars: sidebars.js, sidebars-tickets.js, sidebars-artifacts.js, sidebars-archive.js

## What Does NOT Exist

- `website/sidebars-agent-monitoring.js` — needs to be created
- The fifth plugin-content-docs instance for agent-monitoring
- "Agent Monitoring" navbar entry
- agent-monitoring route in the search plugin's docsRouteBasePath list

## Key Observations

1. The retro dir currently has only `index.md` and `RETRO-ALL.md`. The sidebar can
   use `{type: 'autogenerated', dirName: '.'}` — Docusaurus will discover both files
   automatically. When weekly files (RETRO-2026-W25.md etc.) are added they appear
   without sidebar updates.

2. The `index.md` already has the landing page table. No changes needed to retro files.

3. Search plugin's `docsRouteBasePath` must include `'agent-monitoring'` so retro
   content is indexed.

4. `onBrokenLinks: 'warn'` — safe to add the new plugin without breaking the build
   even if the path has no categories/intro files.
