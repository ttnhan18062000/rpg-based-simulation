# Plan — TCK-20260606-DOCSITE-SCAFFOLD

## Approach

Manual scaffold of a Docusaurus 3 site under `website/`. No `npx create-docusaurus` template — avoids blog plugin, tutorial pages, and dead example content. Four `@docusaurus/plugin-content-docs` instances wired to the four content roots. `@easyops-cn/docusaurus-search-local` for offline full-text search. Two new Makefile targets. Three new `.gitignore` entries.

All open questions are resolved. No unresolved questions remain.

---

## Ordered Steps

### Step 1 — Create `website/` directory and `package.json`

Create `website/` at the project root. Write `website/package.json` manually:
- `name`: `rpg-docsite`
- `version`: `0.0.1`
- `private`: `true`
- `scripts`: `{ "start": "docusaurus start", "build": "docusaurus build", "clear": "docusaurus clear" }`
- No workspace linkage to the root package.json (none exists) or `frontend/`.

### Step 2 — Install npm dependencies inside `website/`

Run inside `website/`:
```
npm install @docusaurus/core@^3.5.2 @docusaurus/preset-classic@^3.5.2 @easyops-cn/docusaurus-search-local
```
This produces `website/node_modules/` and `website/package-lock.json`.

Pin `@docusaurus/core` and `@docusaurus/preset-classic` to `^3.5.2`. Commit `package-lock.json` for reproducibility.

### Step 3 — Write `website/docusaurus.config.js`

The config file must contain:

**Top-level fields:**
- `title`: `"RPG Simulation — Docs"`
- `url`: `"http://localhost:3000"`
- `baseUrl`: `"/"`
- `onBrokenLinks`: `"warn"` (not `"throw"` — many legacy docs lack cross-links; `warn` prevents build failure during scaffold)
- `onBrokenMarkdownLinks`: `"warn"`
- `organizationName` / `projectName`: omit (no GitHub Pages deployment)

**`themeConfig.navbar`:** links to `/docs/`, `/tickets/`, `/artifacts/`, `/archive/`

**`plugins` array — four `@docusaurus/plugin-content-docs` instances:**

| id | path | routeBasePath | exclude |
|---|---|---|---|
| `docs` | `../docs` | `docs` | `['archive/**', 'superpowers/specs/**']` |
| `tickets` | `../tickets/done` | `tickets` | none |
| `artifacts` | `../stored_artifacts` | `artifacts` | none |
| `archive` | `../docs/archive` | `archive` | none |

Each instance references its own `sidebarPath` (`sidebars.js`, `sidebars-tickets.js`, `sidebars-artifacts.js`, `sidebars-archive.js`).

**`themes` array — search plugin:**
```js
[
  require.resolve('@easyops-cn/docusaurus-search-local'),
  {
    hashed: true,
    docsRouteBasePath: ['docs', 'tickets', 'artifacts', 'archive'],
    docsPluginId: ['docs', 'tickets', 'artifacts', 'archive'],
    indexBlog: false,
  },
]
```

**`presets` — disable built-in docs to avoid duplicate plugin-id conflict:**
```js
[
  '@docusaurus/preset-classic',
  {
    docs: false,
    blog: false,
    theme: { customCss: [] },
  },
]
```

### Step 4 — Write four sidebar stub files

Write `website/sidebars.js`, `website/sidebars-tickets.js`, `website/sidebars-artifacts.js`, `website/sidebars-archive.js`.

Each file exports a single autogenerated sidebar:
```js
module.exports = {
  mainSidebar: [{ type: 'autogenerated', dirName: '.' }],
};
```

The sidebar ID key (`mainSidebar`) is consistent across all four files for this ticket. Ticket 7 will replace these with structured definitions.

### Step 5 — Write `website/src/pages/index.js`

Minimal homepage with:
- Page title: `"RPG Simulation — Documentation"`
- Four navigation links rendered as cards or a list:
  - **Docs** → `/docs/` — Project mechanics, engine contracts, architecture
  - **Tickets** → `/tickets/` — Closed ticket history
  - **Artifacts** → `/artifacts/` — Investigation, plan, test-plan artifacts
  - **Archive** → `/archive/` — Historical archived docs
- No Docusaurus blog, no tutorial references.

Use Docusaurus `@theme/Layout` and plain JSX — no custom CSS framework dependency.

### Step 6 — Add `.gitignore` entries

Append three lines to `.gitignore` under a new `# Docusaurus site` comment block:
```
# Docusaurus site
website/node_modules/
website/build/
website/.docusaurus/
```

Place the block after the existing `frontend/` gitignore entries for logical grouping.

### Step 7 — Add `docs-serve` and `docs-build` Makefile targets

**Location:** Add a new `# ── Documentation Site ──` section after the `# ── Quality ──` section, before `# ── Agent Monitoring ──`.

**Targets:**
```makefile
# ── Documentation Site ───────────────────────────────────

docs-serve: ## Start Docusaurus dev server (http://localhost:3000)
	cd website && npm start

docs-build: ## Build Docusaurus static site to website/build/
	cd website && npm run build
```

**Update `.PHONY` line** at the top of the Makefile to include `docs-serve docs-build`.

Pattern follows existing `install-fe` / `build` / `lint` / `typecheck` — all use `cd <dir> && npm <command>`. No Python venv activation needed.

### Step 8 — Verify Gate 1: `make docs-serve` starts without errors

Run `make docs-serve`. Confirm:
- Docusaurus dev server starts on `:3000`
- All four plugin instances initialize without `Error:` lines
- Homepage loads at `http://localhost:3000`
- Each section (`/docs/`, `/tickets/`, `/artifacts/`, `/archive/`) is reachable

Expected runtime: ~10–20 seconds for initial compilation.

### Step 9 — Verify Gate 2: `make docs-build` produces a static build

Run `make docs-build`. Confirm:
- Exit code 0
- `website/build/index.html` exists
- `website/build/docs/`, `website/build/tickets/`, `website/build/artifacts/`, `website/build/archive/` directories exist
- Search index file exists (`website/build/search-index.json` or `search-index-*.json` if hashed)

### Step 10 — Verify Gate 3: gitignore coverage

```bash
git check-ignore -v website/node_modules website/build website/.docusaurus
```
All three must return a matching rule. Run `git status` to confirm none of the three appear as untracked.

### Step 11 — Verify Gate 4: existing frontend targets unaffected

```bash
make install-fe   # exit 0
make lint         # exit 0
make typecheck    # exit 0
```

Confirm the `clean` target does not reference `website/` by inspection.

### Step 12 — Run anti-drift guard checks

```bash
grep -c "plugin-content-docs" website/docusaurus.config.js   # Expected: 4
grep "docsRouteBasePath" website/docusaurus.config.js          # Expected: array with all 4 paths
grep "website/" .gitignore                                     # Expected: 3 entries
grep "^.PHONY" Makefile | grep -c "docs-serve"                # Expected: 1
git diff requirements.txt                                      # Expected: empty
```

### Step 13 — Run scoped Python regression tests

```bash
python3 -m pytest tests/ -m "architecture" -v --tb=short
python3 -m pytest tests/ -m "catalog or content_graph" -v --tb=short
```

Both must exit 0. This ticket makes no Python changes — these confirm no import or structural regressions from workspace-level file additions.
