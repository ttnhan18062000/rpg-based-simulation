## 3. AC-by-AC Complexity Assessment

### AC 1: `make docs-serve` — all four sections navigable
**Complexity: Low.** Already works structurally. The four plugin instances and sidebar files exist. The blocker is that sidebars are autogenerated (not layer-grouped). `make docs-serve` is already defined in the Makefile (line 137).

### AC 2: Sidebar for main docs grouped by layer
**Complexity: Medium.**
- Autogenerated sidebars cannot group by frontmatter field — Docusaurus `autogenerated` only groups by directory.
- The `docs/` tree is not organized by layer directory (files are in `docs/mechanics/`, `docs/engine/`, `docs/core/`, etc. — subdirectories already match layers).
- **Finding:** The docs directory layout already uses layer-named subdirectories (`mechanics/`, `engine/`, `core/`, `architecture/`, `systems/`, `combat/`, `testing/`, `strategy/`, `ai/`, `guidelines/`, `observability/`, `performance/`, `compliance/`). Autogenerated sidebar already produces layer grouping implicitly — the categories will be named after the directory names.
- Custom sidebar is needed only to: (a) rename categories to title-case, (b) reorder them (mechanics first, engine second, etc.), (c) exclude excluded dirs.
- Approach: Python script `tools/generate_sidebar.py` that reads REGISTRY.yaml and emits a static `website/sidebars.js` with explicit `category` entries per layer, each containing their docs in priority order. Alternative: use Docusaurus `_category_.json` files per subdirectory to set label/position — no custom script needed.
- **Decision for plan:** Use `_category_.json` files (one per layer subdirectory) to set label and position. This is zero-Python, zero-build-step, and survives re-runs. No script needed.

### AC 3: Tag index pages
**Complexity: Low.** Docusaurus built-in. Tags frontmatter field is already correctly named (`tags: [...]`) in the files that have it. Enabling tag pages requires no config change — they are enabled by default in plugin-content-docs. The tag index at `/docs/tags/` will automatically appear.
- **Caveat:** Only 10 docs currently have tags. The tag index will work but be sparse. This is a data quality issue, not a site issue.

### AC 4: Status badges on every page
**Complexity: Medium-High** (depends on approach).

Options evaluated:
- **Option A: MDX component `<StatusBadge />`** — requires every `.md` file to become `.mdx` or to use MDX in frontmatter. Docusaurus 3.x supports MDX in `.md` files by default but the component must be imported or globally registered. Global registration via `src/theme/MDXComponents` is the cleanest approach — wrap the existing `MDXComponents` and inject `StatusBadge` globally. The component reads `frontmatter.status` via `useDoc()` hook. **Does not require converting files to `.mdx`.**
- **Option B: CSS-only via remark plugin** — a remark plugin that prepends a `<div class="status-badge status-{value}">` node to every page's AST based on frontmatter. No React required, works with plain `.md`. Simpler but less React-idiomatic.
- **Option C: Swizzle `DocItem/Layout`** — wrap the layout component to inject badge above content. Cleanest for "shows in page header" AC. Requires `npm run swizzle -- --eject`.

**Decision for plan:** Option C (swizzle `DocItem/Layout`) is the most reliable for "shows in page header" across all four plugin instances. Swizzle is safe for this use — it's a thin wrapper, not a core component rewrite.

**Caveat on "search result previews":** `docusaurus-search-local` generates a static index — it does not execute React components. Badges will not appear in search previews. This AC sub-item should be deferred or removed as infeasible without a custom search plugin.

### AC 5: Artifact section — tickets as parent with children
**Complexity: Medium.**
- 469 stored_artifact directories total; 319 have all three files (investigation.md, plan.md, test_plan.md); 150 are partial.
- Docusaurus autogenerated sidebar already renders each ticket directory as a collapsible category containing its files. This partially satisfies the AC.
- The missing piece is a **landing page per ticket** — clicking the ticket category should show a page summarizing the ticket with links to the three artifacts.
- **Option b from ticket (generate index.md pages):** A script `tools/generate_artifact_pages.py` reads REGISTRY.yaml ticket entries, finds artifact_files, and writes `stored_artifacts/{ticket_id}/index.md` with a title and links. This is straightforward — 319 directories need pages. The script can be idempotent (skip if index.md exists and is newer than registry).
- **Risk:** 150 partial directories (missing one or more artifact files) — the script must handle these gracefully (list only present files).

### AC 6: Search across all four sections
**Complexity: Low.** Already configured — `docsRouteBasePath: ['docs', 'tickets', 'artifacts', 'archive']` and `docsPluginId` both set. No code change needed, verify by running a search after startup.

### AC 7: P0 docs appear before P2 historical in search
**Complexity: High — defer.**
`docusaurus-search-local` builds a lunr.js index from file content. It does not support frontmatter-based boosting natively. Custom boosting would require either: (a) forking the plugin, (b) preprocessing the lunr index JSON to adjust term frequencies, or (c) using a different search plugin (Algolia). All are out of scope for this ticket tier. **Decision: defer to a follow-up ticket.** Note in implementation notes.

### AC 8: Archive visually differentiated
**Complexity: Low.** Custom CSS targeting the `/archive/` route prefix. Add a CSS rule to `website/src/css/custom.css` (create if not present) that applies a muted color scheme or banner to archive pages. Can also use a `_category_.json` approach or a global announcement banner.

### AC 9: `make docs-build` — static build, no broken links
**Complexity: Medium.** `onBrokenLinks` is currently set to `'warn'` (not `'throw'`). The main risk is: (a) generated index.md files referencing artifact files that don't exist, (b) sidebars.js referencing doc IDs that don't exist after filtering. Must verify after implementation. `website/build/` should be in `.gitignore`.

### AC 10: `docs/README.md` updated
**Complexity: Trivial.** The file already references `make docs-serve` in its intro (confirmed in head -40 output). Update is minimal — add a direct link line and remove the manual navigation map section, which is now superseded by the site.
