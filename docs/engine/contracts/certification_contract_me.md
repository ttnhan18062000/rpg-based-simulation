# Proof System Contract - [Milestone E]

## Purpose
This contract establishes the "Final Law" for the v2 engine's proof and certification system. It transforms the certification harness and documentation integrity checks into a rigorous production-readiness gate.

## Scope
Milestone E covers the final consolidation of the certification, conformance, and reporting layers. It ensures all production claims are evidence-backed, hardware-bound, and immune to documentation drift.

## 1. Machine-Readable Certification Law
- **Source of Truth**: The structured JSON proof bundle generated by the `CertificationHarness` is the authoritative source of truth. Human-readable reports are derivative.
- **Proof Bundle Directory**: A valid proof must reside in `reports/release_proof/` and contain:
  - `release_proof.json`: Multi-scenario results, environment metadata, and conformance status.
  - `release_report.md`: Scoped human-readable summary.
  - `manifest_snapshot.json`: Copy of the manifest used for the run.
- **Commit Provenance**: Every artifact MUST contain the `commit_sha`. The production gate MUST verify that this SHA matches the candidate being released.

## 2. Scenario Expectation Law
- **Explicit Cadence**: `required_sampling_interval_ticks` must be defined for every scenario.
- **Allowed Failures**: Scenarios must explicitly declare `allowed_failure_kinds` (e.g., `NONE` for release-gate scenarios).
- **Recovery & Equivalence**: Expectations must define `recovery_time_limit_ticks` and `reproducibility_required` (True for authoritative baseline matching).

## 3. Conformance Law
- **Multi-Dimensional evaluation**: Conformance is PASS only if:
  1. **Envelope**: No measurement point exceeds profile limits.
  2. **Sequence**: Degradation modes were entered in the correct priority order.
  3. **Recovery**: System returned to `NORMAL` within the time limit.
  4. **Equivalence**: Final state hash matches the sequential baseline (bit-identical).
  5. **Completeness**: No telemetry gaps exceed the scenario-defined interval.

## 4. Failure Taxonomy Law (`FAILED_*`)
- **Precise Reason**: No vague failure states are allowed. Every failure must have a structure `FailureKind` and an actionable `failure_reason`.
- **Standardized Naming**:
  - `FAILED_ENVELOPE`
  - `FAILED_DEGRADATION_SEQUENCE`
  - `FAILED_RECOVERY_TIMEOUT`
  - `FAILED_SEMANTIC_DRIFT`
  - `FAILED_TELEMETRY_GAP`

## 5. Honest Reporting Law (Scoped Claims)
- **Quadrants of Truth**: Every performant claim MUST specify:
  1. `RuntimeProfile`
  2. `CertificationScenario`
  3. `HardwareClass`
  4. `OverrideStatus`
- **Vanity Prohibition**: Terms like "universal scaling", "unlimited performance", or "fastest" are forbidden.
- **Recorder Enforcement**: The `CertificationRecorder` logic MUST reject attempts to emit claims missing the above scoped metadata.

## 6. Production-Readiness Gate
- **Target-Driven**: The release gate is driven by `declared_release_targets` in `manifest.json`.
- **Evidence Requirement**: A release is blocked unless a valid, passing, fresh (matching `commit_sha`) Proof Bundle exists for every declared target.
- **Integrity Requirement**: Any documentation drift detected by the integrity suite blocks the release.

## 7. Serialization Safety Law

- **No Deep-Copy of Live State**: `CertificationResult.to_artifact_dict()` MUST build its output field-by-field using `getattr()`. Calling `dataclasses.asdict()` on any object that holds a reference to live `AuthoritativeState` is forbidden — it triggers deep traversal and unbounded memory amplification.
- **`final_state` field is always `null` in the proof bundle**: Even when a final state is captured, it is never embedded in `proofs_bundle.json`. It is written to a separate side-file under `<output_dir>/state/` only when `EvidenceLevel.FULL` is requested.
- **Recorder consumes dict directly**: `CertificationRecorder.record()` accepts a dict from `to_artifact_dict()` — not a JSON-serialised/deserialised roundtrip via `to_json()`.

## 8. Evidence Level Law

Proof capture depth is controlled by `EvidenceLevel` (passed to `run_scenario()` and `to_artifact_dict()`):

| Level | What is captured |
|---|---|
| `SUMMARY` (default) | Scalar metrics only. `final_state_summary` contains entity/resource/region counts. No state file. |
| `COMPACT` | SUMMARY + `entity_sample` (top 5 by ID ascending) + `resource_snapshot` (top 5 nodes by quantity descending). No state file. |
| `FULL` | COMPACT + writes `CanonicalStateHasher.to_canonical_data()` to `<output_dir>/state/<run_id>.final_state.canonical.json`. `final_state_hash` (SHA-256) added to bundle entry. Write failure is non-fatal. |

`EvidenceLevel.SUMMARY` is always backward-compatible — callers that do not pass `evidence_level` receive SUMMARY behaviour unchanged.

## 9. Manifest Snapshot Law

- **Implementation**: `CertificationHarness` writes `<output_dir>/manifest_snapshot.json` as a verbatim copy of the source manifest after the proof bundle is recorded.
- **Injectable path**: The manifest source path defaults to `docs/engine/manifest.json`. It can be overridden via the `manifest_path` constructor argument (used in tests).
- **Non-fatal**: If the manifest file is absent or the write fails, a warning is logged and the certification run continues normally. The run must not fail due to manifest snapshot write errors.

## Non-Goals
- No gameplay or actor-logic changes.
- No distributed cluster orchestration certification.
- No weakening of earlier milestone resource laws.
