# Idea: Visual/Geometric Quality Validation — a Consumer of the World Rendering Core

> **Maturity: IDEA** — Not scheduled. Standalone from the SimQ roadmap; see `experiments/spatial_rendering/PROPOSAL.md` for the full investigation trail and prototype code this doc distills. **This is one major use case built on top of `idea_world_rendering_core.md`** (same folder) — it is not the whole of that vision. See the core doc for the rendering mechanism itself (architecture options, real technical grounding, benchmarked performance, drawing-tool options); this doc covers only the validation-specific scope: what "good" and "bad" mean geometrically, how it's scored, and how an agent reviews it.

---

## Problem

SimQ's 10 pillars are exclusively event-stream-driven and have zero spatial/geometric coverage — confirmed by reading every pillar definition (`src/simulation_quality/pillars.py`) and the `WORLD` pillar's real event list (`calamity_spawned`, `region_trauma_delta`, `ecology_cycle_completed`, ...), all region-level statistics, no geometry. The prior SimQ pillar-completeness investigation (`TCK-20260707-SIMQ-PILLAR-COMPLETENESS-DOC`) never considered a spatial pillar.

No mechanism exists to answer "does this generated world look reasonable" — geometrically coherent biome shapes, plausible entity distribution, an actually-alive population — or to inspect an entity's behavior over time as a reviewable image sequence.

**Real evidence this is a live, not hypothetical, gap** (full corpus sweep across all 15 worlds in `data/worlds/` with non-`PLAIN`-only content — 3 worlds are pure `PLAIN`, correctly excluded as having no biome shape to measure — `experiments/spatial_rendering/PROPOSAL.md` §5c, re-verified 2026-07-16):
- 26 of 33 measured biome components (78.8%) score a bounding-box fill-ratio ≥0.95 — near-perfectly rectangular, not organic. **Every one of the 7 components below 0.95 is `FOREST` type; zero exceptions exist among `CAVE`/`RUIN`/`MOUNTAIN`/`SWAMP` components (all ≥0.98 across the full corpus).** `FOREST` is visibly generated by a different mechanism than every other biome type: rendered and inspected several of the lowest-scoring components directly rather than trusting the number alone — `frontier_extended` (0.584), `sandbox_world` (0.819), and `wilderness_survival` (0.775) are each a composite of 2–4 joined rectangular stamps forming an L-shaped or staircase outline, not organic terrain, not a single rectangle either.
- In `dungeon_crawl`, two `FOREST` components are the *same shape* — one is the other rotated exactly 90 degrees, confirmed via coordinate transpose match. Template reuse, not independent generation.

## Idea

Given the rendering core exists (`idea_world_rendering_core.md`), this consumer defines **pure visualization/geometry validation, zero data-lookup checks.**

### Scope: pure visualization/geometry, zero data-lookup checks

Any check reducing to "does field X belong to allowed-set Y" is explicitly out of scope here, no matter how spatial it sounds — including placement legality (routed to `HardLawMonitor`, see `../archive/idea_placement_legality_check.md` — shipped, archived 2026-08-20) and biome-resource content correctness (routed to an extension of the existing `CatalogValidator`, which already validates this relationship at the static-catalog level but not at compiled-instance level). A fact you can look up in data should never be approximated by looking at pixels.

**Four metric families, all tested against real compiled worlds, not just designed:**

| Family | Metric | Real result |
|---|---|---|
| **Shape** | Connected-component-aware bounding-box fill-ratio; repetition/rotation detection | 78.8% of components ≥0.95 fill-ratio corpus-wide, 100% for non-`FOREST` types; `FOREST` component duplication found in `dungeon_crawl` |
| **Density** | Entity nearest-neighbor coefficient of variation; terrain-type histogram | `sandbox_world` 0.648, `dungeon_crawl` 0.678 |
| **Variants** | Trail-activity liveliness; cross-*spec* diversity (terrain-histogram total variation distance) | An entity found stuck in a 2–3 tile cluster for 100+ ticks; TVD(sandbox, dungeon)=0.2315 confirms the metric detects genuine variation. Terrain layout is deterministically fixed per world spec, not seed-randomized (confirmed via 3-seed comparison) — diversity is a cross-*spec*, not cross-*seed*, question for this signal |
| **Connectivity** | Whole-map walkable-region connected-component count | `dungeon_crawl`: 1 component, 100% of 15,245 walkable tiles reachable — a real *passing* result, not just failures |

Four additional candidates (boundary fractal complexity, whole-map mirror symmetry, render color-contrast legibility, bounds-utilization) were tested and resolved: three adopted (symmetry — clean negative, no artificial mirroring after baseline-adjustment; bounds-utilization — 100% on the one world with declared topology dimensions; color-contrast — caught and fixed a real bug, a `GRASS`/`PLAIN` color collision in prototype code, confirmed `GRASS` unused by any tested world), one tested-and-not-recommended (boundary fractal dimension — validated against synthetic controls but too weak a signal at this project's map scale, ~0.03–0.05 spread vs. real coastlines' ~1.2–1.3). Elevation-based metrics were checked and ruled inapplicable — this engine's terrain is a flat categorical classification with no continuous elevation field.

### Scoring: a sibling system to SimQ, not an 11th pillar

Reuses SimQ's exact grade-band vocabulary (`S`/`A`/`B`/`C`/`D`/`F`, same numeric thresholds — `docs/simulation_quality/quality_scoring_contract.md` §4.5) for consistency, but is an independent implementation: SimQ is architecturally exclusively event-stream-driven (`ObservabilityEventEnvelope` → scorer); these metrics compute directly from `AuthoritativeState` geometry with no natural event to hang them on. Forcing an artificial event to fit SimQ's shape would repeat a scope-violation this project's own SimQ investigation already identified and avoided for a structurally identical reason (determinism was excluded from SimQ for the same "correctness property, not a health gradient" reasoning).

**Signal shape**, following `WORLD DYNAMICS`'s own `Signal | Delta | Tag` table format: unlike SimQ's mostly-monotonic signals, fill-ratio and clustering-CV have a *healthy range*, not a "more is better" direction — both a near-perfect-rectangle and a scattered-noise extreme are penalized, only trail-activity behaves like SimQ's classic dormancy shape (`entity_stagnant`, mirroring `calamity_dormant`'s `-8` pattern).

### Agent-first review pipeline

**Agent-vs-human review**: tested, not assumed to be interchangeable. A coordinate-gridded/annotated variant converts a vague visual impression into a precise, citable claim (e.g. "biome seam at x=90–95, y=20–60") — the *default* Tier-2 output, since agent review is the stated priority (accuracy + cost) over human review. A plain variant remains available for human/opt-in use. A tiered pipeline (Tier 0 pure data → Tier 1 compact JSON digest → Tier 2 actual image, fetched only on escalation) minimizes token/context cost between agent steps, reusing this project's own existing static-check-then-escalate pattern.

**Agent role**: no existing subagent has any image capability; the closest structural template is `.claude/agents/simulation-analyst.md` (Data Sources → Analysis Dimensions → Severity Classification → structured Output) — a real, reusable shape, not a pattern to invent.

## Architecture Constraints

- Must not perform any data-lookup validation (biome-resource matching, etc.) — routed to `CatalogValidator`.
- Must not perform binary placement-legality checks — routed to `HardLawMonitor` (`../archive/idea_placement_legality_check.md` — shipped, archived 2026-08-20).
- Must reuse the rendering core's already-proven determinism, `DirtySet` incremental caching, and `data/runs/` storage convention (`idea_world_rendering_core.md`) — this consumer adds no new rendering-mechanism requirements of its own.
- Test classification (`docs/testing/test_taxonomy.md`, checked directly): performance work fits the existing `tests/perf/` + `perf_budget` fixture convention exactly; metric-correctness tests (fill-ratio, connectivity, CV, symmetry) are ordinary `tests/unit/` tests, no `tests/parity/` marker required; the render-determinism golden-hash test (owned by the core doc) is a natural `regression`-marker candidate.

## Open Questions

- Exact digest JSON schema and the Tier 0→2 escalation threshold (e.g. what fill-ratio value triggers fetching the real image) — not calibrated.
- Exact healthy-band threshold numbers for all four metric families, and whether `FOREST` needs its own, separate threshold band from other biome types given its structurally different (composite-stamp) generation pattern. Fill-ratio now has real evidence across all 15 worlds with measurable biome content (single-seed); the other three families remain tested on 1–3 worlds; none have multi-*seed* calibration for any world yet — needs the same real-corpus-calibration discipline SimQ itself used (`tools/calibrate_simq.py` across multiple seeds).
- Whether `FOREST`'s distinct multi-rectangle-composite generation pattern (vs. every other biome type's clean single rectangle) points to a specific, fixable difference in `src/worldgeneration/generator.py`'s placement logic for that one type — not investigated, a real, sharper follow-up lead than "biome placement in general looks stamped."
- Whether this becomes a real `.claude/agents/world-render-reviewer.md` file, or folds into an existing agent's scope.
- Exact terrain-string vocabulary is still not exhaustively enumerated across every world (only sampled, not walked systematically against `src/worldgeneration/generator.py`'s full output space) — shared open question with the core doc.
