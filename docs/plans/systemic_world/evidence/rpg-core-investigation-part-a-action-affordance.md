## A3. Architectural assessment

Weighing the five outcomes named in the source instruction, without presupposing a winner, against
the evidence traced above:

1. **"Existing Rules and domain mechanisms are sufficient; only local wiring/contract repairs are
   needed."** — Strong support from this pass's own evidence. AGENCY-01/02/03/04's target
   semantics (decision stages are causally distinct; opportunity ≠ affordance; motivation
   influences, doesn't determine; decision validity ≠ outcome) are already frozen Catalog content
   and, per AGENCY-03's own repository-evidence section, largely realized — the one Rule-boundary
   violation found (`AGENCY-03`'s CONFLICTING perception-bypass finding) is a wiring defect against
   an already-correct Rule, not a missing Rule. **`PROPOSED`, moderate-to-high confidence**: this
   pass found no cross-domain invariant violated by the *existence* of multiple independent action
   paths (`ActionRouter` vs. direct pipeline-phase calls) — each documented instance (Guild visit,
   Objective Reward) states an explicit, principled reason for bypassing `ActionRouter`
   (`WorkerPacket`'s own bounded-context law), not an accident.

2. **"A small engine-level attempt/resolution contract would remove proven duplication."** —
   **Partial support, already attempted once.** `TCK-20260401-ACTION-CONVERGENCE` (DONE,
   2026-04-01) already unified `ConflictResolver`/authoritative-apply/replay-consistency once, with
   a verified acceptance criterion ("replay recovery produces bit-identical matching world state").
   `TCK-20260422`'s own `ActionProposal`/`ActionType` was a *second*, later attempt at a shared
   typed intent/verb model — but, per this pass's own zero-caller finding, it was never actually
   adopted by the live `ActionRouter` dispatch, which still uses raw payload strings. **The
   concrete duplicated behavior a new contract could fix, evidenced this pass**: `execute_interact`
   uses no `kind` discriminator at all (harvest/craft/loot/rest-at-structure are indistinguishable
   at the intent layer, resolved only later by target-object type in `InteractionSystem.enforce()`)
   — a real, minor duplication-of-responsibility case, not a large one. **`PROPOSED`, low-to-moderate
   confidence**: the *concrete* case for a new contract is thin (one already-built, unused model;
   one minor discriminator gap) — this looks more like "finish adopting what was already built" than
   "design something new."

3. **"A separate affordance/action semantic layer is justified by a real cross-domain invariant."**
   — **Not supported by this pass's evidence.** No cross-domain invariant was found broken by the
   current split (Combat/Harvest through `ActionRouter`, Quest generation/reward through direct
   pipeline phases) — each split point has its own stated architectural reason. **`PROPOSED`, low
   confidence that this is currently justified**, contingent on Part B's own findings (if Part B
   finds recognition/observation genuinely needs a new cross-domain "this was an observable action"
   concept spanning all three families uniformly, that could change this answer — not settled by
   Part A alone).

4. **"One or more existing World Rules are ambiguous, or a genuine post-freeze semantic gap is
   demonstrated."** — **One real ambiguity found, characterized precisely per the source
   instruction's rule 5**: AGENCY-03 already states Opportunity/Actionable-Affordance as two
   distinct tiers, and already correctly diagnoses the CONFLICTING perception-bypass finding — no
   *new* Rule gap was found this pass beyond what AGENCY-03 already documents. The minimal
   counterexample this pass can offer: `execute_interact`'s missing `kind` discriminator is an
   **implementation observation, not a Rule ambiguity** — no Catalog Rule requires interaction
   intents to carry a domain-specific kind at the intent layer; this is a code-cleanliness/
   architecture question, the same category AGENCY-05's own "capability estimation is scorer-local"
   finding was classified under, not a Rule-boundary question.

5. **"No shared abstraction should be added yet."** — **This pass's own recommendation, `PROPOSED`,
   moderate confidence**: given (a) a prior unification effort already exists and partially
   succeeded (TCK-20260401), (b) a second, typed model already exists and was never adopted
   (TCK-20260422's `ActionProposal`), and (c) no cross-domain invariant was found broken by the
   current multi-path structure — the evidence points toward **finishing or retiring the existing
   unused `ActionProposal` model** (a decision for the roadmap owner, not this pass) rather than
   designing a third abstraction. This is offered as this pass's own weighted read of the evidence,
   not a `DECIDED` outcome.

**If any shared contract is proposed downstream of this report**, its minimum invariant should be:
*every action attempt is validated against current state at the moment of execution, not only at
the moment of decision* (matching the Combat posture-recheck fix's own already-proven value,
`TCK-20260915`) — leaving reward/consequence shape, timing semantics, and domain-specific resolution
entirely to domain owners. **Case where it must not apply**: `GuildAction.visit()`'s own direct
pipeline-phase pattern, which exists specifically *because* it needs broader state access than any
bounded per-attempt contract could provide by design — imposing a uniform attempt/resolution
contract there would violate `WorkerPacket`'s own stated law, not fix anything.

**Open boundary, not settled by this pass's traces**: whether deliberate entity actions generalize
to reflexes, coercion, organizational decisions, and environmental processes. AGENCY-02's own Scope
Boundary explicitly defers non-ordinary override mechanisms (reflex/compulsion/mind-control) as
undesigned; this pass found no evidence either confirming or ruling out that the same
`ActionRouter`/domain-handler shape would suit those cases. **`UNKNOWN`, left open.**
