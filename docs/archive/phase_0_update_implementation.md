- The chosen-entity viewer requirement is not met.
The high-level plan says the chosen-entity view should answer who the entity is, what it wants, what changed it, what is at risk, and what it might do next, showing current goal, emotional trend, notable relationships, recent major memories, traits, routine, ongoing arc, and likely next choices. The current inspector only shows general info, biological needs, social bonds, and the last 10 memory logs. That is a debug panel, not the curated spectator lens both the high-level plan and Phase 0 require. 
- The salience story is overstated.
The plan claims salience is enforced via impact and “weighted pruning in MindAspect.” But MindAspect.prune_memories() just sorts by absolute impact. The weighted salience logic exists in MemorySalienceService, but that service is separate, labeled Phase 2, and the AI path shown here calls actor.mind.prune_memories() instead. Worse, combat handling also hard-truncates memory logs to the last 50 entries, ignoring salience entirely. So the plan’s wording overclaims what is actually wired. 
- The mutation-discipline story is not clean enough yet.
AIBrain says it is “stateless and side-effect free,” but it directly calls actor.mind.prune_memories(). That is a mutation during AI deliberation. Separately, ActionSystem directly appends trauma/survival InterpretedEvent entries into target.mind.narrative.memory_log, instead of keeping all meaning-bearing changes inside typed update objects. That is exactly how hidden coupling creeps back in.
- There is a real runtime defect in the social update path.
ActionSystem does old_vals, new_vals = world.social_registry.update_bond(...), but SocialRegistry.update_bond() shown in the bundle does not return anything. That is not a design nit. That is a concrete bug in the authoritative social pipeline.
- WorldLoop is carrying dead or divergent registry wiring.
WorldState already owns social_registry, and ActionSystem reads world.social_registry. But WorldLoop also stores a separate _social_registry from constructor input, and in the reviewed code I do not see it being assigned back into world.social_registry. That means the injected registry can be ignored, duplicated, or drift from the real source of truth
