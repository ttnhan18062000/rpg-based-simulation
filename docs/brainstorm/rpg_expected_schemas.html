Expected Data Schemas

Field-level schemas for the atlas's proposed ideas — not prose descriptions of target behavior, but the actual typed shape each feature needs, so ambiguity like "is City a kind of Region or does Region contain Cities?" gets caught before a ticket is written, not after.

Prompted directly by that exact ambiguity surfacing in idea 66. Scoped to the 9 highest-leverage proposed ideas that introduce genuinely new durable state — the ones most load-bearing for everything downstream, not all ~30 ideas that eventually need this treatment. See "Not yet scoped" at the end for the honest remainder.

New — no equivalent exists in code today Reused — an existing real class/field, unchanged Extended — an existing field/enum gains a new value Open question — a real design decision not yet made

Region & Place

Idea 66. Replaces today's flat model — where a City is a Region, not a place inside one — with Region as a territory container holding zero or more Places. This is the schema that triggered this whole document, so it's worked out in the most detail.

The Durable State Rule (CLAUDE.md) argues for a registry index either way — worth deciding before idea 66 gets ticketed, not during implementation.

Race Relations

Idea 37 — wires race into the hostility scoring that already reads it. Flagged elsewhere in this atlas as the single highest-risk unanchored number in the whole roadmap: up to 156 directed pairs (13 real races) with zero existing signal anywhere in the content catalog to anchor them.

RaceRelations new, static content

FieldTypeDescriptionStatus
race_relationsDict[Tuple[str, str], float]Directed pair (race_a, race_b) → hostility bias. Up to 13×12 = 156 directed pairs for the real 13-race catalogNew
value rangefloatNot yet decided — likely [-1.0, 1.0] (hate↔ally) or [0.0, 1.0] (neutral→hostile), matching whichever existing hostility-scoring convention engine/legality.py already usesOpen question
default_relationfloatWhat two races with no explicit entry default to — needed since authoring all 156 pairs by hand for launch is unrealisticOpen question

Storage location is itself undecided: a field on RaceDefinition can't hold pairwise data cleanly (it's inherently a relationship between two races, not an attribute of one) — more likely a standalone RaceRelationsRegistry, the same shape as the existing faction-relationship matrix already backing Diplomacy. Consumed by engine/legality.py's existing hostility scoring, which already reads race but has no data source to read from yet.

Reproduction

Idea 32 — the atlas's own read: "the most numerically loaded idea in the set." Strictly sequenced after idea 43 (population_cohorts seeding), since individual births need to feed back into the aggregate signal that gates them.

BirthEvent new

FieldTypeDescriptionStatus
parent_a_entity_id, parent_b_entity_idstrThe two parentsNew
birth_cooldown_ticksintPer-parent cooldown — no existing precedent for the value, though the hard-requirement-check shape matches harvesting/contractsNew, free creative territory
population_pressure_gatefloatWhether the region can support a birth right nowReused: migration_threshold = 0.7, already coded in demographics/cohort.py
genetic_inheritance_weightfloatHow much of each parent's attributes the child inheritsReused but never-tuned: the real 0.8–1.3 multiplier range in the orphaned GeneticsSystem
child_entity_idstrThe newly constructed entityNew

Real unresolved gap, not just an open question: until idea 43 ships, this event has nothing to gate against — population_cohorts is empty in every world today, so population_pressure_gate would always read a null signal. Idea 32 cannot be corpus-tested until both idea 43 and itself exist, confirmed by M8's own investigation.

Marriage

Idea 33 — the simulation's first real propose/accept relationship event. Same interaction shape as idea 13's Team-Up invite/accept (see schema 9) — worth building both on one shared pattern rather than two bespoke ones.

MarriageState new

FieldTypeDescriptionStatus
proposer_entity_id, target_entity_idstrThe two entitiesNew
statusenumPROPOSED | ACCEPTED | REJECTEDNew enum
married_tickOptional[int]Set when status becomes ACCEPTEDNew
eligibility_gatefloatMinimum SocialBond.sentiment/familiarity required before a proposal can even be attemptedReused as the gate; reads existing entity.social state

Shared-implementation opportunity: the propose/accept/reject state machine here is structurally identical to idea 13's Team-Up Invite/Accept below — same three states, same affection-gate pattern. Worth a single shared ProposalState base shape rather than two independent implementations, even though the domains differ.
