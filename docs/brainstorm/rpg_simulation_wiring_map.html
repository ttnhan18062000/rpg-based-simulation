RPG Simulation · High-Level System Overview

How Every Layer of the Simulation Actually Wires Together

A grounded, high-level map of the whole system — Entity, Group, Faction, Region, City, Race, Clan, World, World Objects — and the real connections between them, followed by a drill-down into one layer (Entity) showing its own tick-by-tick loop and lifecycle arc in detail. Built from the real codebase, not the design docs' word alone.

How this was built. A read-only investigation traced every real transition and mechanism in the codebase — several claims in the docs turned out stale against the actual code, and are corrected here. Every node and edge below is tagged LIVE (runs in production sims today), PROPOSED (a design idea, not yet built), GATED (coded but behind a feature flag defaulting OFF), or ORPHANED/BROKEN (code exists but has zero callers, is structurally empty, or doesn't do what it looks like it does) — and every non-LIVE claim is cited to a real file and line.

Entity detail: the operating loop

The Layer Model above shows how Entity connects outward. This section and the next drill into the Entity layer itself.

What an entity does every tick, in three layers: THINK (perceive, recall, decide), ACT (once readiness allows it), and BUILDUP — the slow accumulation from Act's outcomes that feeds back into how the entity thinks and acts next time. Follow the loop: THINK → ACT → BUILDUP → back into THINK.

New finding

Permadeath doesn't actually end an entity. When a Hero at generation 4+ takes a lethal hit, combat.py:187–188 sets outcome_kind="PERMADEATH" and writes is_permadeath=True — but LifecycleSystem.resolve_lifecycle() (lifecycle.py:43) only deactivates an entity when outcome_kind=="KILL". "PERMADEATH" never reaches that check.

Net effect: the entity keeps lifecycle.active=True and keeps acting in the simulation. is_permadeath is written once and never read anywhere else in the codebase. No HP reset, no deactivation, and succession (heir transfer, T15) never triggers — it's gated on the same dead-check that only fires for old age or an ordinary kill.

This wasn't previously documented anywhere in this session's investigation — found while tracing the lifecycle graph specifically, not while auditing combat.
