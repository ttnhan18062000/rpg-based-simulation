# TCK-20260607-MON-DASHBOARD

## Title
Agent Monitoring — Integrate retro reports into Docusaurus site

## Status
DONE

## Tier
standard

## Type
feature

## Priority
P2

## Request Summary
Add `agent-monitoring/retro/` as a Docusaurus content root so weekly retro Markdown files appear in the docs site under a dedicated "Agent Monitoring" section. Minimal integration — no custom components needed.

## Scope

### Docusaurus plugin instance
Add a fifth `@docusaurus/plugin-content-docs` instance to `website/docusaurus.config.js`:

```js
{
  id: 'agent-monitoring',
  path: '../agent-monitoring/retro',
  routeBasePath: 'agent-monitoring',
  sidebarPath: require.resolve('./sidebars-agent-monitoring.js'),
}
```

### Sidebar
`website/sidebars-agent-monitoring.js`:
- Grouped by year, then week (autogenerated from file names `RETRO-YYYY-WNN.md`)
- Most recent week first

### Navigation
Add "Agent Monitoring" link to the Docusaurus top navbar alongside Docs, Tickets, Artifacts.

### `docs/agent-monitoring/` integration
The schema and retro-guide docs in `docs/agent-monitoring/` are served through the main docs plugin instance (not the agent monitoring instance). The monitoring instance only serves the retro reports themselves.

### Index page
`agent-monitoring/retro/index.md` — auto-generated by `generate_retro.py` as a table of all retro files (date, run count, DONE rate, top issue).

## Out of Scope
- Custom dashboard components (charts, graphs) — plain Markdown tables are sufficient
- Real-time feed
- Authentication/access control
- Search tuning for monitoring content (low-value, low query volume)
