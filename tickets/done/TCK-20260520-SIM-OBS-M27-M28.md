# TCK-20260520-SIM-OBS-M27-M28

## Title

Implement Storage Export Layer and Local Analytics with Parquet and DuckDB (Milestones 27-28)

## Status

DONE

## Request Summary

Implement a clean storage export abstraction (ArtifactExporter) enabling run/sweep artifact conversions to JSONL and Parquet formats (Milestone 27), and build a local analytics engine (AnalyticsDatasetBuilder and DuckDBQueryService) that Normalizes these artifacts into high-performance Parquet tables for local SQL evaluation without adding a database server (Milestone 28).

## Scope

- **Storage Export Abstraction**:
  - Define `ExportJob` model tracking `export_id`, `source_run_id`, `source_sweep_id`, `source_path`, `output_path`, `format`, `artifact_types`, `created_at`, `status`, and `errors`.
  - Define `ExportManifest` schema saved as `exports/<export_id>/export_manifest.json` tracking outputs, skipped files, and record counts.
  - Implement an extensible `ArtifactExporter` registry to parse and export JSONL and Parquet formats.
- **Local Parquet & DuckDB Analytics**:
  - Implement `AnalyticsDatasetBuilder` normalizing raw sweep directories and runs into standard `runs`, `metric_windows`, `anomalies`, and `simulation_events` tables.
  - Write high-performance, cleanly schemas-typed Parquet files under `data/analytics/<dataset_id>/` along with a `dataset_manifest.json`.
  - Implement `DuckDBQueryService` loading the Parquet tables to support predefined, JSON-safe analytical queries:
    - `worst-runs`: Runs sorted by health score ascending and warning/critical counts.
    - `anomaly-summary`: Count of anomalies grouped by rule ID and severity.
- **CLI Commands**:
  - Register new subcommands to the main CLI parser:
    - `rpg-observe export <run_id> --format <jsonl|parquet>`
    - `rpg-observe export-sweep <sweep_id> --format <jsonl|parquet>`
    - `rpg-observe build-dataset <sweep_id>`
    - `rpg-observe query-dataset <dataset_id> --query <worst-runs|anomaly-summary>`
- **Test Coverage**:
  - Implement unit test suites verifying the exporter, registry error handling, dataset builder, and query execution.
  - Implement integration test suites confirming CLI command executions and proper exit code compliance.

## Out of Scope

- Implementing ClickHouse database servers or S3 cloud storage sinks.
- Event stream adapters (Kafka/Redis streams) (Milestone 29).
- Out-of-process anomaly worker daemon execution (Milestone 30).
- Historical query API endpoints (Milestone 31).

## Acceptance Criteria

- **Milestone 27 (Storage Export)**:
  - Single-run and sweep exports resolve correctly to JSONL and Parquet.
  - An `export_manifest.json` file is compiled, recording exact output files, record counts, and skipped files.
  - Invalid formats or unsupported artifact types raise clean, descriptive validation errors.
  - CLI `export` and `export-sweep` subcommands work correctly and output matching paths.
- **Milestone 28 (Local Analytics)**:
  - `AnalyticsDatasetBuilder` successfully converts a complete sweep directory into four normalized Parquet tables.
  - A `dataset_manifest.json` is generated listing table paths and precise record counts.
  - `DuckDBQueryService` executes both `worst-runs` and `anomaly-summary` queries correctly, returning JSON-safe result dictionaries.
  - CLI `build-dataset` and `query-dataset` commands run without error and display formatted results.
- **Verification**:
  - All unit and integration tests pass successfully in `.venv/bin/pytest`.
