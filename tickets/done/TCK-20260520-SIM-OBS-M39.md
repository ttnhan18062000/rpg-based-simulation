## Request Summary

Create a practical Single-Page Application (SPA) dashboard containing 5 distinct views to support simulation inspection, report browsing, sweep/baseline comparison, historical event search, and entity timelines.

## Scope

- Build a polished, responsive, glassmorphic Single-Page Application (SPA) shell at `/api/v1/observability/ui` containing 5 views:
  1. **Live Run Overview**: Show running status, current tick, real-time tick compute average, memory RSS, current system cadence/governor mode, active counters (anomalies, violations, errors), and the real-time event ticker.
  2. **Run Report Browser**: Query all completed runs using the `/api/v1/observability/history/runs` endpoint. Let the user inspect individual run details including the full health score, anomaly summary, and hard law violations.
  3. **Sweep / Baseline Comparison**: Query all historical scenario sweeps via `/api/v1/observability/history/sweeps`. Display sweep summary statistics, baseline comparison ratios, worst-performing seeds, health score distributions, and failed expectation rules.
  4. **Historical Event Search**: Integrated, paginated search interface utilizing the `/api/v1/observability/search/events` and `/api/v1/observability/search/anomalies` endpoints to search across runs by tick range, severity, and event type.
  5. **Entity Timeline**: Full timeline view aggregating both events and anomalies chronologically for any selected entity ID, integrating with `/api/v1/observability/search/entity-timeline`.
- Implement responsive layout with curated professional color schemes (dark mode, glassmorphic styling, smooth CSS transitions, custom Google Fonts).
- Ensure all interactive elements have unique and descriptive IDs for automated/browser testing.

## Out of Scope

- Changing internal simulation engine gameplay logic.
- Building a complex authentication layer.

## Acceptance Criteria

- Serves the Single-Page Application at `/api/v1/observability/ui` and `/api/v1/observability/live/ui`.
- All 5 dashboard views operate correctly, handling zero-states and asynchronous query latency gracefully.
- Visual elements meet high-quality UI design guidelines (no generic un-styled HTML, usingOutfit/JetBrains fonts, smooth animations, precise badges).
- Standard unit and smoke integration tests assert endpoints are accessible and functional.
