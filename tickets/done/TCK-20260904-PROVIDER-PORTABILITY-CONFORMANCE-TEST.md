## Request Summary
docs/architecture/agent_orchestration_contract.md's Provider-Adapter Boundary ADR requires .claude/ and .codex/ to stay thin translations of the shared agent-orchestration/ contract on 4 named axes (workflow phases, terminal statuses, gate policy, artifact requirements), enforced today only at the field-name level. The plan calls for a test diffing .claude/agents/*.md and .codex/config.toml's translated equivalents against the canonical contract. Investigation found the literal framing doesn't match reality on two points: .codex/config.toml is deliberately empty of phase/gate/status content by design (the real Codex-side translated artifact is the generated AGENTS.md), and the gate-policy/artifact-requirement axes aren't yet represented as structured, diffable fields anywhere in agent-orchestration/ — building a real diff for those 2 axes may require first extending the contract schema itself. This ticket retargets the Codex-side comparison at AGENTS.md and reuses the existing TCK-20260721-CLAUDE-CONFORMANCE-ADAPTER pattern and divergence-approval mechanism for the 2 new axes.

## Scope
- Write a new conformance test extracting per-phase/per-role gate conditions from implement-ticket.js (or agents/*.md where documented) and assert they match agent-orchestration/'s per-phase gate representation — if that representation doesn't exist yet as a structured field, either add it to contract.yaml/roles/*.yaml (with a versioning bump per agent-orchestration/README.md's bump rule) or explicitly scope that as a prerequisite step within this ticket
- Write a new conformance test extracting the required-artifact set per tier (plan.md/investigation.md/test_plan.md for standard/epic, none for hotfix) and assert it matches a corresponding agent-orchestration/ field
- Include at least one deliberately-introduced-mismatch fixture per new axis proving the test actually fails on a real divergence, not just passes today
- Retarget the Codex-side comparison at AGENTS.md (the real translated artifact generated by tools/agent_orchestration_codex_adapter/generator.py), or explicitly document why .codex/config.toml is a no-op check and redirect to AGENTS.md
- Reuse the existing agent-orchestration/intentional-divergences.md approval mechanism for the 2 new axes (gate_policy, artifact_requirements) rather than inventing a new one
- Diff live code -> contract (matching the 2 existing Claude tests' direction), not the reverse

## Out of Scope
- Rebuilding or duplicating the 2 already-covered axes (workflow phases, terminal statuses) — TCK-20260721-CLAUDE-CONFORMANCE-ADAPTER already built these
- Treating .codex/config.toml as if it holds real phase/gate/status content — it is deliberately inert per TCK-20260721-CODEX-GUIDANCE-FIXTURE-CAPTURE
- Inventing a new divergence-approval mechanism when agent-orchestration/intentional-divergences.md already exists and should be reused
