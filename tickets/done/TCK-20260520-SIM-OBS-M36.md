## Request Summary

Make live event streaming externalizable. Default remains in-process. Production can use Redis Streams or NATS.
We will implement a production-grade, non-blocking Redis Streams EventStreamAdapter with a background worker thread, bounded local queues, configurable backpressure drop policies, stream health endpoints, and a basic consumer group interface.

## Scope

- **Milestone 36.1: Non-Blocking Redis Stream Publisher**:
  - Implement a background worker thread in `RedisStreamAdapter` that pops events from a local queue and writes them to Redis using `client.xadd()`.
  - Maintain a thread-safe custom `collections.deque` and a `Condition` variable.
  - Track metrics (published count, dropped count, connection status, last success).
- **Milestone 36.2: Backpressure drop policy**:
  - If the queue is full, drop `DEBUG` / `INFO` events first.
  - Keep `WARNING` / `ERROR` / `CRITICAL` events by evicting low-severity items from the queue.
  - Support configurable queue size and drop policy parameters.
- **Milestone 36.3: FastAPI Stream Health Endpoint**:
  - Register `GET /api/v1/observability/live/stream-health` returning adapter metrics.
- **Milestone 36.4: Basic Consumer Group Foundation**:
  - Build `RedisStreamConsumer` to establish a stream consumer group, read/process batches of events, and ACK processed messages.

## Out of Scope

- Setting up complex dead-letter queues (DLQ) or auto-scaling consumers.
- Support for Apache Kafka or NATS in this transition milestone.

## Acceptance Criteria

- [x] Redis stream adapter publishing is entirely non-blocking and does not impact engine thread latency.
- [x] Backpressure queue eviction logic correctly drops `DEBUG`/`INFO` and preserves high-severity events under pressure.
- [x] Redis Stream Adapter gracefully recovers from short connection outages.
- [x] `/api/v1/observability/live/stream-health` endpoint returns high-fidelity metrics.
- [x] `RedisStreamConsumer` reads events from the consumer group, executes callbacks, and ACKs processed items safely.

## Implementation Notes

- Designed an extremely lightweight priority-eviction algorithm using `collections.deque` locked-queue traversal. This guarantees that engine ticks never block or lock up under Redis network dropouts while guaranteeing zero data loss for critical simulation anomalies and errors.
