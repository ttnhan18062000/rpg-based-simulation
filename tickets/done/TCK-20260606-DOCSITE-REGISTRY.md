## Request Summary
Build a Python script that reads frontmatter from all content types (docs, tickets, artifacts, archive) and generates a flat `docs/REGISTRY.yaml`. Update CLAUDE.md and the relevant agents to use the registry for fast doc discovery without reading 542 files.

## Scope

### Registry generation script
`tools/generate_registry.py`:
- Walks frontmatter-tagged content roots: `docs/`, `tickets/done/`
- Does NOT walk `stored_artifacts/` directly — artifacts are joined from `tickets/done/` by ticket_id (see below)
- Reads frontmatter from each `.md` file
- Emits a flat YAML list with one entry per file

**Doc entry schema:**
```yaml
- type: doc
  path: docs/mechanics/02_combat_laws.md
  title: Combat Laws
  status: authoritative
  layer: mechanics
  authority: P0
  audience: developer
  tags: [combat, damage, durability]
  last_verified: 2026-06-06
```

**Ticket entry schema** (joined with stored_artifacts by ticket_id):
```yaml
- type: ticket
  path: tickets/done/TCK-20260606-PHASE26-REGISTRY-ADAPTERS-REPAIR.md
  ticket_id: TCK-20260606-PHASE26-REGISTRY-ADAPTERS-REPAIR
  title: Phase 26 Registry Adapter Repair
  tier: standard
  type: chore
  priority: P1
  date: 2026-06-06
  related_code_areas:
    - src/core/registries.py
  artifact_files:
    - stored_artifacts/TCK-20260606-PHASE26-REGISTRY-ADAPTERS-REPAIR/investigation.md
    - stored_artifacts/TCK-20260606-PHASE26-REGISTRY-ADAPTERS-REPAIR/plan.md
    - stored_artifacts/TCK-20260606-PHASE26-REGISTRY-ADAPTERS-REPAIR/test_plan.md
  tags: []
```

The `artifact_files` list is generated by checking which files exist under `stored_artifacts/{ticket_id}/` at registry generation time. Tickets with no artifact folder (hotfix tier or old tickets) emit `artifact_files: []`.

This join is the canonical link between tickets and their artifacts. Agents and Docusaurus use this — not directory scans of `stored_artifacts/`.

- Sorts by `type` (doc first, ticket second), then `authority`/`priority`, then `path`
- Reports count by type/status/layer/authority at the end
- Exits non-zero if any in-scope doc file is missing frontmatter (CI gate); ticket files without full frontmatter emit a warning but do not fail (backward compat with pre-schema tickets)

## Assumptions / Open Questions
- `docs/REGISTRY.yaml` should be committed to git (not gitignored) so agents can read it without running the script
- `tickets/todos/` and `tickets/inprogress/` are NOT indexed — only `done` tickets are stable references
- `stored_artifacts/` is NOT walked directly — it is joined from `tickets/done/` by ticket_id at registry generation time
- `artifact_files` is a presence check at generation time; if a file is added to stored_artifacts/ later, registry must be regenerated
- How often should the registry be regenerated? Manually via `make docs-registry` for now; CI hook is future work
- Tickets without `## Related Code Areas` emit `related_code_areas: []` — no error

## Implementation Notes

- `tools/generate_registry.py` imports `extract_frontmatter` from `validate_frontmatter.py` via `sys.path.insert`. Uses PyYAML if available; falls back to manual YAML serialisation (stdlib-only).
- 8 doc files were found without frontmatter during Step 3 (docs/agent-monitoring/*, docs/certification/, docs/content/, docs/design/, docs/investigation/, docs/migration/). Frontmatter added inline to unblock CI gate; these were missed by prior FM-LIVE work.
- Ticket entry `type` key collision resolved: internal field for ticket kind (bug/feature/etc.) kept as `ticket_type` in Python and emitted as `ticket_type` in YAML; entry kind remains `type: ticket`.
- One ticket (TCK-20260606-DOCSITE-FM-TICKETS.md) has missing frontmatter — emits a warning (non-fatal per backward-compat rule).
- Registry output: 912 entries (255 doc, 657 ticket). Exits 0.
