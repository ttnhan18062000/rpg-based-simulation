# TCK-20260628-E41F-PARTY-SCORER

## Status

## Priority

## Request Summary
No `PartyCompositionScorer` existed. `FORM_PARTY` route existed in schema/mapper
but was never generated by the route generator. This ticket implements both:
the scorer service and its integration into adventure route generation.

## Scope
1. `src/systems/social_systems/party_composition.py` — PartyRole enum +
   PartyCompositionScorer (role diversity + OCEAN compatibility scoring).
2. `src/domains/adventure/generator.py` — emit FORM_PARTY route when
   entity sociability ≥ 0.2 and allied candidates exist in state.
3. Tests.

## Out of Scope
- Cohesion threshold adjustment (E41G).
- Multi-hero orchestration (E41H).

## Acceptance Criteria
- [x] `PartyCompositionScorer.score([...])` returns 0.0–1.0.
- [x] `infer_party_role()` maps guard→TANK, mage→HEALER, hero(low-brave)→DPS, worker→SUPPORT.
- [x] Balanced party scores higher than homogeneous party.
- [x] `FORM_PARTY` route generated for entities with sociability ≥ 0.2 when candidates exist.
- [x] `FORM_PARTY` NOT generated when sociability < 0.2.
- [x] Route `expected_benefit` reflects composition score.
- [x] 228 social + adventure tests pass.

## Implementation Notes
- FORM_PARTY route was mapped in schema.py and mapper.py but never generated.
  Discovery: grep for FORM_PARTY in generator.py returned nothing before this fix.
- Entity kind is at `entity.kind`, not `entity.identity.kind` — important for role inference.
- Candidates capped at 8 to avoid O(N) blowup in large worlds.
- `entity.is_alive` checked via `getattr(e, "is_alive", True)` to handle EntityState
  variants that may not expose the attribute directly.
