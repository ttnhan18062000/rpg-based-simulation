## Request Summary
Implements `MilitaryConflictPhase`: war declaration, entity squad commitment, siege mechanics, and territory transfer via authoritative pipeline.

**Requires:** TCK-20260619-E53B-DIPLOMACY

## Scope

**MilitaryConflictPhase** at governance layer (after `FactionDecisionPhase`):
- War declaration: `FactionDirective(WAR_DECLARED, target_faction)`
- Squad commitment: commit GUARD + WARRIOR entities near contested region via `GroupRecord.roles["FACTION_SQUAD"]`
- Siege mechanics: besieging faction reduces target region's `service_availability` by 5% per tick; defender emits reinforcement directives
- Territory transfer: `WorldUpdate.owner_faction_id_set` applied via authoritative pipeline when `siege_progress ≥ 1.0` (no new RegionSovereigntyUpdate type needed — existing `WorldUpdate` field covers this)

**War exhaustion**: `FactionState.military_strength -= 0.001 per tick at war`. Incentivizes peace when `military_strength < 0.3`.

**Combat**: faction squads use standard damage formula from `docs/mechanics/02_combat_laws.md`. Do NOT special-case siege combat.

## Out of Scope
- Chronicle naming of wars and alliances (E53D)
- Player faction control
- Multi-wave sieges on the same region after transfer

## Implementation Notes
Scoped into 4 child standard tickets (strict linear dependency chain: Ca→Cb→Cc→Cd):
- **E53Ca**: `MilitaryConflictPhase` class skeleton + engine wiring (phase detects WAR pairs; no mutations yet)
- **E53Cb**: `SiegeState` frozen dataclass, `RegionState` additions (`siege_state`, `service_availability`), `WorldUpdate` additions, squad `GroupRecord` commitment, per-tick siege degradation and defender reinforcement
- **E53Cc**: `siege_progress ≥ 1.0` territory transfer trigger (`WorldUpdate.owner_faction_id_set`), `FactionUpdate.territory_add/remove`, `TERRITORY_TRANSFERRED` WorldEvent, `NarrativeLedger` wiring, 3-faction integration test
- **E53Cd**: `military_strength_delta -0.001/tick` drain, `SEEK_PEACE` directive emission at `< 0.3`, `DiplomaticStateMachine` WAR→NEUTRAL handling, `WAR_ENDED_EXHAUSTION` WorldEvent, `test_war_exhaustion_ends_conflict`

Key architectural decisions documented in `stored_artifacts/TCK-20260619-E53C-WAR/investigation.md`:
1. `MilitaryConflictPhase` is a sub-phase of `TickPhase.INIT` (TickPhase frozen)
2. `SiegeState` is a durable frozen sub-record on `RegionState` (not flat fields)
3. `service_availability: float = 1.0` on `RegionState`, degraded via `WorldUpdate.service_availability_delta`
4. Territory transfer uses existing `WorldUpdate.owner_faction_id_set` (no new update type)
5. Squad commitment uses existing `GroupRecord.roles` with value `"FACTION_SQUAD"`
6. War exhaustion emits `SEEK_PEACE` directive to existing `DiplomaticStateMachine`; no duplicate state machine logic
