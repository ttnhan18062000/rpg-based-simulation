# TCK-20260520-SIM-OBS-M40

## Title

Alert Routing and Incident Workflow (Milestone 40)

## Status

DONE

## Request Summary

Implement the AlertRouter, AlertDeduplicator, AlertEvent, and Sinks (LogAlertSink, WebhookAlertSink) to route serious Observatory findings (such as HardLawViolation, WatchdogTrip, CriticalAnomaly, and StreamBackpressureHigh) to external logging and alert endpoints.

## Scope

- Implement `AlertEvent` dataclass containing alert_id, alert_type, severity, run_id, message, evidence, dedup_key, and created_at.
- Implement `AlertDeduplicator` supporting sliding window/TTL suppression to ignore duplicate alerts within a configurable time window.
- Implement `AlertRouter` supporting sink registration, alert deduplication, severity filtering, and tracking delivery status.
- Implement `LogAlertSink` to write structured alert details to application logs.
- Implement `WebhookAlertSink` to asynchronously POST JSON payloads to external URLs with timeout and retry limits.
- Integrate alert generation into existing systems: Hard Law violations, Watchdogs, Live Anomaly Worker critical anomalies, and Stream Backpressure issues.
- Expose the alert router in a clean way so that the API or engine can hook into it.

## Out of Scope

- Integrating with heavy external third-party alert services (like PagerDuty, OpsGenie) directly (this should be handled via the WebhookAlertSink).
- An interactive UI for alert acknowledging/silencing (out of scope for V1).

## Acceptance Criteria

- [x] `AlertEvent` serializes to JSON correctly.
- [x] `AlertRouter` routes alerts to registered and enabled sinks.
- [x] `AlertDeduplicator` suppresses duplicate alerts with the same `dedup_key` within the suppression interval (default 60 seconds).
- [x] `LogAlertSink` writes alerts to log outputs.
- [x] `WebhookAlertSink` successfully POSTs JSON to a destination URL and handles timeout/retry failures gracefully without throwing unhandled exceptions.
- [x] Hard Law violations, critical worker anomalies, and backpressure issues generate structured alerts through the router.
- [x] Exhaustive test coverage exists in unit and integration suites.

## Assumptions / Open Questions

- Webhook endpoint URL, enabled status, and deduplication timeout are configurable via environment variables (`SIM_ALERTS_*` / `RPG_ALERTS_*`).
- Deduplication state resides in memory for simplicity ("simple-now").
- WebhookAlertSink dispatches HTTP calls asynchronously via ThreadPoolExecutor to avoid blocking the simulation kernel.

## Implementation Notes

- AlertEvent provides 4 factory methods: `create_hard_law_violation`, `create_watchdog_trip`, `create_critical_anomaly`, `create_stream_backpressure`.
- AlertRouter applies severity threshold → deduplication → dispatch to sinks pipeline.
- All integration points are wrapped in `try/except` to guarantee alerts never break the engine or workers.
- WebhookAlertSink uses exponential backoff retry (0.5s * attempt) up to `max_retries` attempts.
- AlertsManager is a lazy singleton configured from environment variables.
