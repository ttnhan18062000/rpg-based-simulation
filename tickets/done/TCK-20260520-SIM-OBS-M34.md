## Title

Establish Warehouse Adapter and Schema Stabilization (Milestone 34)

## Status

chore

## Priority

## Request Summary

Prepare the RPG simulation's Observatory for an external high-volume event warehouse by defining the `WarehouseAdapter` base abstract interface, stabilizing logical schemas into versioned models, introducing a schema version validation registry, and developing an ingestion dry-run verification mode.

## Scope

- **Milestone 34.1: Warehouse Adapter Interface**:
  - Defined abstract base class `WarehouseAdapter`.
  - Included methods: `ingest_run(run_id)`, `ingest_sweep(sweep_id)`, `query_runs(filter)`, `query_events(filter)`, `query_anomalies(filter)`, `health()`, and `close()`.
- **Milestone 34.2: Stable Record Models**:
  - Implemented Pydantic-based record models that represent stabilized warehouse table structures:
    - `RunRecord`
    - `SweepRecord`
    - `EventRecord`
    - `MetricWindowRecord`
    - `AnomalyRecord`
    - `HardLawViolationRecord`
    - `BaselineRecord`
    - `ComparisonRecord`
- **Milestone 34.3: Warehouse Schema Registry**:
  - Implemented a registry validating incoming and outgoing schema versions.
  - Refuses incompatible versions safely and issues explicit error messages.
- **Milestone 34.4: Ingestion Dry-Run Mode**:
  - Developed a dry-run ingestion engine that reads run/sweep artifacts, performs schema validations, maps them to warehouse records, reports record counts, and executes with zero database mutations.

## Out of Scope

- Implementing the concrete ClickHouse event warehouse backend (reserved for Milestone 35).
- Implementing external NATS or Redis Streams consumer daemons (reserved for Milestone 36/37).

## Acceptance Criteria

- `WarehouseAdapter` abstract interface can be subclassed by future databases (like ClickHouse or Postgres) [MET].
- Logical record models maintain payload fields as JSON strings to avoid excessive flattening [MET].
- Incompatible schema files fail safely with explicit, descriptive version mismatch errors [MET].
- Dry-run mode successfully simulates run/sweep ingestions, returning full records validation statistics [MET].
- All new unit and integration tests execute successfully [MET].
