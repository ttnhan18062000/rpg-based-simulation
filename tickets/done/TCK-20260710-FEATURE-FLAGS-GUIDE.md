## Request Summary
Feature-flag documentation is currently scattered across four locations: the `FeatureFlagManager`/`FeatureMode` contract in `docs/simulation/domains/optimization_contract.md`, the default-OFF policy in `docs/engine/known_limitations.md` §1.5, the DEV-002 decision record in `docs/guidelines/intentional_divergences.md`, and the SimQ per-world flag-activation mechanism (`config/simulation_quality/profiles/*.yaml` + `tools/calibrate_simq.py::_load_profile_feature_flags()`). Consolidate these into one authoritative guide at `docs/guides/feature_flags.md`. Separately, fix a stale filename citation — several docs (including `CLAUDE.md` itself) cite `docs/guidelines/v2_intentional_divergences.md`, but the real file has no `v2_` prefix (`docs/guidelines/intentional_divergences.md`). Also investigate whether `docs/combat/rollout_hardening_rulebook.md`'s `SimulationConfig.overhaul_features` is the same flag system as `FeatureFlagManager` or a separate one, to decide whether to fold it into the new guide or just cross-reference it.

This construct appears to exist only in that one doc, with no corresponding implementation found. Treated as a genuinely separate (and possibly stale/unimplemented) system from `FeatureFlagManager` — cross-referenced with a caveat, not folded in. If a differently-named implementation is later found, this ticket's scope decision should be revisited.
- **`docs/audits/D06_longrun_health.md`**: named as a suspect file in the request, but grep confirms no `v2_intentional_divergences` string present. Assumption: no change needed to this file; it was likely conflated with another audit doc when the request was drafted.

- **No parity ledger impact**: confirmed this is documentation-only with no behavior change; `docs/parity_ledger/infrastructure.yaml` and `social_narrative.yaml` entries that reference DEV-002 already cite the correct (non-`v2_`) filename, so no ledger edit is required.
