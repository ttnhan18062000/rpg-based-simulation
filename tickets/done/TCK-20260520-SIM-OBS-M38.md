# TCK-20260520-SIM-OBS-M38

## Title

Historical Event Search API

## Status

DONE

## Request Summary

Expose warehouse-backed historical search APIs to allow developers to query events, anomalies, runs, entity timelines, and metric trends across multiple simulation runs. The endpoints must prefer ClickHouse when enabled, fallback to local JSON/JSONL file artifacts when using the local backend, support cursor-based or offset-based pagination, enforce strict alphanumeric identifiers to prevent path traversal, and implement audit logging for queries.

## Scope

- Implement stable query routing logic that checks `ObservabilityConfig.get_warehouse_backend()`:
  - If `"clickhouse"`, route queries to ClickHouse.
  - If `"local"`, parse, filter, and page records from local JSONL/JSON artifacts in the run repository.
  - If `"null"`, return empty results or appropriate indicators.
- Implement five primary FastAPI search endpoints in `src/api/routes/search.py`:
  1. `GET /api/v1/observability/search/events`: Filters by `run_id`, `entity_id`, `tick_start`, `tick_end`, `severity`, and support pagination (`limit`, `offset`).
  2. `GET /api/v1/observability/search/anomalies`: Filters by `run_id`, `rule_id`, and support pagination.
  3. `GET /api/v1/observability/search/runs`: Filters by `scenario_name`, `status`, and support pagination.
  4. `GET /api/v1/observability/search/entity-timeline`: Aggregates and sorts all events and anomalies for a given `entity_id` across a `run_id`.
  5. `GET /api/v1/observability/search/metric-trend`: Returns `metric_windows` timeseries trend metrics for a given `run_id`.
- Implement robust input validation (enforce valid alphanumeric `run_id` and `sweep_id` to block path traversal).
- Implement standard query audit logging to log search types and bounds without flooding Loki with high-cardinality values or large result payloads.
- Integrate the router into `src/api/server.py`.

## Out of Scope

- Implementing an arbitrary SQL ad-hoc execution endpoint.
- Developing the UI search pages (covered in Milestone 39).

## Acceptance Criteria

- All five search endpoints function correctly and return standard, structured JSON-safe payloads.
- Input validation blocks invalid IDs and tick ranges.
- Local fallback allows developers to search run events and anomalies directly from local files without requiring a ClickHouse database.
- Search queries are thoroughly logged with structured audit records.
- Integration tests confirm both ClickHouse (mocked/if active) and local fallback adapters execute queries accurately.
